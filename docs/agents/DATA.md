# Finding real data (dev stack)

Run SQL with `just db sql [--slot N | --db NAME] "<sql>"` (or `-f file.sql`): the slot's database, Unicode-safe,
`|`-separated with a header, read-only as `ashyq_ro` (emails, bios, IPs and secrets are not readable: select named
columns, find people by `username`); `--rw` runs as the owner for writes and email lookups. Sign in as anyone
with `just login-as <username|email> [slot]`; screenshot pages with
`just shoot`. Real data: a slot on a local restored copy (`just stack up 1 --db <name>`, RUNBOOK 5.3); change its rows
freely, never production's.

Every table, column, key and foreign key with the table's purpose: `docs/agents/SCHEMA.md` (generated by
`just schema-docs`; search it before guessing a column). Tables sit in schemas by area (`core`, `learning`, `ai`,
`analytics`, `ops`; ARCHITECTURE §8 rule 8) and the database's `search_path` covers them: write `users`, not
`core.users`; in a catalog query filter `relnamespace::regnamespace::text IN ('public', 'core', 'learning', 'ai',
'analytics', 'ops')`, never `= 'public'`. A database cloned with plain `CREATE DATABASE ... TEMPLATE` lacks the path
(`just db fresh` copies it; else `SELECT ensure_app_search_path()` as the owner).

## Where things live

| Word in the UI                    | Table / column                                                                       |
| --------------------------------- | ------------------------------------------------------------------------------------ |
| course, its picture               | `courses` (`public`, `archived_at`; `thumbnail_image_key` under `/content/<key>`)    |
| chapter, activity                 | `chapters`, `activities` (`activity_type`, `activity_sub_type`, `published`, `content`) |
| enrolled learner                  | `trail_runs` (`user_id`, `course_id`); per activity: `trail_steps`, `activity_progress` |
| course teacher / author           | `course_staff` (`course_id`, `user_id`, `authorship`, `status`)                      |
| enrolled learner                  | `enrolments` (`course_id`, `user_id`; staff excluded by `is_course_staff`); the learner's list: `trail_runs`; per activity: `completions` (the fact), `activity_progress` (projection), `trail_steps` (legacy marks) |
| course teacher / author           | `resource_authors` (`course_id`, `user_id`, `authorship`, `status`)                  |
| quiz, exam, code challenge        | `assessments` (`activity_id`, `lifecycle`; title/kind = the activity's) + `assessment_items` (`body` json) |
| code statement, tests, languages  | `assessment_items.body`: `prompt`, `tests[]`, `languages[]`, `time_limit_seconds`     |
| attempt (quiz, exam, code)        | `submissions` (`status` draft / submitted / graded / released / returned; until contract B2 the rows still say `pending` / `published`, the API always does) |
| what an attempt answered against  | `submissions.items_snapshot` / `policy_snapshot`, `assessment_version_id` -> `assessment_versions` |
| a grade and its history           | `grading_entries` (journal, latest id = current) = `submissions.final_score`; breakdown `submission_breakdown(id, auto_breakdown)` (latest entry's, else the hand-in's) |
| code "Run"                        | `code_runs` (+ `code_run_cases`, `verdict`)                                          |
| file task, its hand-ins           | `file_submissions` (`lifecycle`, `instructions`) + `file_submission_attempts` (`status`, same words as `submissions`) |
| lesson media                      | `activities.content->>'filename'` (video, PDF), `blocks.content` (page blocks)       |
| role, permission                  | `user_roles` -> `roles` (`slug`); permissions in `role_permissions`                 |
| group                             | `usergroups`, `usergroup_members`, `usergroup_courses`                               |
| course progress                   | `course_progress` (`progress_pct`, `completed_at`)                                   |

A learner sees an activity when it is `published` and, for a file task, its `file_submissions.lifecycle` is
`published`; an assessment needs `assessments.lifecycle = 'published'`.

## Ready queries

A user's id and roles:

```sql
select u.id, u.username, string_agg(r.slug, ',') from users u left join user_roles ur on ur.user_id = u.id
left join roles r on r.id = ur.role_id where u.username = '<login>'
group by 1, 2
```

Published activities of a type in courses a user is enrolled in (types: dynamic, video, document, quiz, exam,
code_challenge, file_submission):

```sql
select a.course_id, a.id, a.name from activities a join enrolments t on t.course_id = a.course_id
join users u on u.id = t.user_id where u.username = '<login>'
and a.activity_type = 'code_challenge' and a.published limit 5
```

Activities with learner work, most first (good review data):

```sql
select s.assessment_id, a.activity_id, count(*) from submissions s join assessments a on a.id = s.assessment_id
group by 1, 2 order by 3 desc limit 5
```

Courses a teacher can edit:

```sql
select c.id, c.name from courses c join course_staff cs on cs.course_id = c.id
join users u on u.id = cs.user_id where u.username = '<login>' and c.archived_at is null
```

Make a file task reviewable (published, with instructions and a deadline in 3 days; `just db sql --rw`):

```sql
update activities set published = true where id = '<activity>';
update file_submissions set lifecycle = 'published', published_at = now(), instructions = 'Ответьте на вопросы.',
  max_files = 2, due_at = now() + interval '3 days' where activity_id = '<activity>';
```

Media referenced by the database but missing from local storage: `just restore-media --slot N` copies them from
production's public `/content/` (a sample, size-capped).

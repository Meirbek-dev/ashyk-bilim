# ТЗ: импорт тестов из Excel в формате DOT

Статус: объём и решения согласованы 2026-11-13 (раздел 17); реализовано 2026-11-13. Разделы 7 и 8 описывают
сделанное; где остальные разделы расходятся с кодом, прав код (`crates/xlsx`, `assessments/imports.rs`,
`assessments/draw.rs`, `features/assessment-import`).
Образец: `Java_EXAM_2026_2.xlsx` (экзамен, 64 вопроса, 6 картинок). Сам файл в репозиторий
не коммитится: это реальный экзамен (см. 12.6).
Источник формата: DOT (`dot-experiment-main`), `docs/legacy/03-tests.md` BR-TST-38…41, импортёр
`apps/api/app/Modules/Tests/Support/TestSpreadsheetImporter.php`.

## 1. Цель

Преподаватели уже держат банки вопросов в Excel в формате DOT и загружают их в dot.tou.edu.kz. Нужно, чтобы
тот же файл без правок загружался в Ashyq и становился тестом или экзаменом. В попытку при этом должна попадать
случайная выборка вопросов, а время, число попыток и картинки должны переноситься из файла.

Результат для преподавателя: файл → предпросмотр с ошибками по ячейкам → «Создать» → готовая к публикации
активность в главе курса. Результат для студента: попытка из N случайных вопросов банка с таймером и картинками.

## 2. Что есть сейчас

| Возможность | DOT | Ashyq сейчас |
|---|---|---|
| Импорт из Excel | есть, без предпросмотра | нет (никакого импорта, нет xlsx-крейтов; есть `zip`, `quick-xml`) |
| Банк + случайная выборка N из M | `tests.limit`, уровни сложности | нет: каждый студент видит все вопросы |
| Вопрос: один ответ / несколько | типы 1, 2 | `choice` (`multiple`, `variant`) |
| Короткий текстовый ответ с автопроверкой | тип 3 | нет (`open_text` уходит на ручную проверку) |
| Сопоставление | тип 4 (L≠R, «лишние» элементы) | `matching` только пары 1:1 |
| Развёрнутый ответ | тип 5 (любой непустой — верно) | `open_text` (ручная проверка) |
| Картинки в вопросе и варианте | есть | нет полей; `/content/` в markdown промпта, без учёта ссылок |
| Перемешивание | всегда | `randomize_questions`, `randomize_options` (детерминированно по user) |
| Частичные баллы за «несколько ответов» | нет | `partial_credit` |
| Контроль честности | 8 флагов | флаги в `assessments` |
| Лимит вопросов на тест | 20 000 строк | `MAX_ITEMS = 200` (`assessments/service.rs:28`) |

## 3. Объём

Срок: к ближайшей экзаменационной сессии (декабрь 2026 – январь 2027). Формат DOT поддерживается **полностью**, без
отложенных частей (решение 2026-11-13). Интерфейс один — web-2: прод полностью переведён на него, `apps/web` не меняется.

**Входит:**
- чтение `.xlsx` на сервере (свой ридер на `zip` + `quick-xml`), включая картинки поверх ячеек и «в ячейке» (Excel 365, `richData`);
- строка настроек 1;
- все типы 1–5:
  - 3 — новый вид `short_answer`;
  - 4 — сопоставление с лишними элементами;
- картинки вопроса и варианта;
- выборка N из M, в том числе по уровням сложности (`F1 = 1`, квоты 6.3);
- предпросмотр, затем фиксация (новый тест, замена вопросов, добавление вопросов);
- UI в web-2: импорт, предпросмотр, картинки и многострочные варианты в плеере и редакторе;
- шаблон для скачивания;
- выгрузка теста в тот же формат (`.xlsx`), которую можно загрузить обратно (круговой обмен, как в DOT BR-TST-41).

**Порядок работ.** Каждый шаг заканчивается зелёным `just check` и готов к выкладке сам по себе:
1. Ридер и разбор формата (раздел 4) с полным каталогом сообщений (раздел 10). Код только на сервере, без записи в БД.
2. Модель:
   - `prompt_format`, `media`, точное сравнение вариантов (5.2);
   - `short_answer`;
   - расширение `matching`;
   - медиа-таблица и назначения загрузок.

   Плеер и редактор web-2 показывают новое.
3. Выборка и квоты (раздел 6).
4. Импорт: API, задание, фиксация (разделы 7–9) и UI предпросмотра (11.1).
5. Выгрузка и шаблон; круговой тест «выгрузка → загрузка».
6. Приёмка на образце (раздел 15) на копии прод-данных до объявления преподавателям.

Шаги 1–3 не зависят друг от друга и могут идти параллельно (`just wt new`). Если сроки поджимают, выгрузка (шаг 5)
единственная может выйти после начала сессии: для проведения экзамена она не нужна.

**Позже (не в DOT, отдельной задачей):** анализ вопросов с учётом выборки, выгрузка результатов в xlsx.

**Не входит:**
- `.xls` (BIFF): сообщение «Сохраните файл как .xlsx»;
- окно старта 08:00–22:00 (DOT BR-TST-01);
- «олимпиадный» режим DOT;
- рамки академического календаря;
- `tests_access` (в Ashyq это `assessment_access_*` и `assessment_overrides`);
- глоссарий.

## 4. Формат файла (нормативно)

Совместим с DOT байт в байт по смыслу ячеек. Читается **активный лист** (`workbook.xml` → `bookViews/workbookView/@activeTab`).
Остальные листы игнорируются (info-сообщение с их именами). Строки и столбцы считаются от 1, заголовка нет.

### 4.1 Строка 1: настройки теста

| Ячейка | Смысл | Правило | В Ashyq |
|---|---|---|---|
| A1 | название | обязательна, ≤ 200 символов после trim | `activities.title` (редактируется в предпросмотре) |
| B1 | служебная DOT (`is_free`) | 0, 1 или пусто | игнорируется; другое значение → предупреждение |
| C1 | число попыток | целое ≥ 0 или пусто (→ 0) | 0 → без ограничения (`max_attempts = NULL`); > 10 → предупреждение, ставится 10 (`MAX_ATTEMPTS`) |
| D1 | время, минуты | целое ≥ 0 или пусто | 0 → без лимита; иначе `time_limit_seconds = D1 × 60` |
| E1 | вопросов в попытке | целое ≥ 0, ≤ числа вопросов | 0 или = числу вопросов → выборки нет; иначе `draw_count = E1` |
| F1 | уровни сложности | пусто/0 — выкл., 1 — вкл. | квоты выборки по уровням (6.3); при `E1 = 0` уровни сохраняются, но выборки нет |

«Целое» — число без дробной части, либо строка `^\s*\d+\s*$` не больше 2 147 483 647. Дробное число, отрицательное
число или текст дают ошибку.

### 4.2 Строки 2…n: один вопрос на строку

Пустая строка без картинок пропускается. Строка, где есть хоть одно значение или картинка, — вопрос.

| Столбец | Типы 1, 2, 3, 5 | Тип 4 |
|---|---|---|
| A | текст вопроса и/или картинка(и) в A | то же |
| B | тип: 1 — один ответ, 2 — несколько, 3 — короткий текст, 4 — сопоставление, 5 — развёрнутый | 4 |
| C | 1, 2: номера правильных через `;` (допустим завершающий `;`, пробелы); 1 — ровно один. 3: эталонный текст. 5: игнорируется | пары `лево-право;…`, право может быть 0 |
| D | уровень (пусто/0 при `F1` выкл.; 1, 2, 3, 101, 102, 201, 202 при вкл.) | `L;R` |
| E… | варианты (1, 2) подряд, без пропусков | E — уровень, F… — L левых, затем R правых |

**Правильный ответ задаёт только столбец C.** Жирный шрифт ничего не значит. Если в варианте есть жирный шрифт и он
расходится с C, выдаётся предупреждение `bold_mismatch`. В образце жирный выделяет правильный ответ в строках 2–27,
29–34 и 64–65 и везде совпадает с C; в строках 28 и 35–63 его нет.

### 4.3 Преобразование значений ячеек

| Значение в XML | Результат |
|---|---|
| shared string / inline string / rich text | конкатенация всех `<t>` прогонов |
| число | кратчайшее точное десятичное представление: `310` → «310», `0.1` → «0.1», `1E-7` → «0.0000001»; без «.0» у целых |
| число с форматом даты/времени/процента (`numFmtId` 9–22, 45–47, свои `[$-…]`, `%`, `yy`) | значение как число и предупреждение `number_format` (Excel показывает иначе) |
| boolean | «TRUE»/«FALSE» и предупреждение |
| ошибка (`t="e"`) | ошибка `cell_error` |
| формула (`<f>`) в строках вопросов | ошибка `formula` (как в DOT); в строке 1 берётся закешированное значение |
| ячейка с `vm=` (картинка «в ячейке», Excel 365) | картинка этой ячейки: `xl/metadata.xml` → `xl/richData/rdrichvalue.xml` → `richValueRel.xml(.rels)` → `xl/media/…`; правила 4.5 те же, что для картинок поверх ячеек. Значение `vm=` без картинки (другие rich-типы, например «Акции») → ошибка `cell_error` |

Строка и число с одинаковым видом различаются: в образце E34 = число `310`, F34 = текст `310.0`. Это разные
варианты, оба отображаются так, как набраны.

### 4.4 Нормализация текста

1. `\r\n` и `\r` заменяются на `\n`, а NBSP — на пробел только по краям строки.
2. Варианты и C обрезаются по краям. В образце E5–G5 содержат хвостовые пробелы (`'byte '`): обрезаются, итог — одна info-строка на файл.
3. Текст вопроса обрезается по краям; внутренние переводы строк и отступы сохраняются (код в A28, A55).
4. **Литералы `\n`.** В DOT буквальные два символа `\` и `n` в тексте означают перенос строки, и учителя на это рассчитывают.
   В образце так написаны A53, A54, A55 и A62 (`{\n System.out…`). По умолчанию (режим `dot`) `\n` превращается в перевод
   строки, а затронутые ячейки перечисляются в info-сообщении. В предпросмотре есть переключатель «Не преобразовывать `\n`»
   (режим `none`): он нужен для вопросов, где `"\n"` — часть Java-строки.
5. **Литералы `\"`** (A53, A54) не меняются, но получают предупреждение `suspicious_escape`: DOT показывает их как есть.
6. Сравнение вариантов на совпадение **учитывает регистр**. В A32 варианты `person.age` и `Person.age` разные.
   Текущая проверка готовности `items.rs:553` сравнивает через `to_lowercase()` и заблокирует публикацию такого вопроса.
   Поэтому сравнение меняется на точное после trim, для всех источников, не только для импорта (раздел 5.2).
7. Длина: вопрос, вариант и эталон ≤ 20 000 символов (`items.rs:27`), иначе ошибка.

### 4.5 Картинки

- Берутся из `xl/drawings/drawingN.xml` листа: `xdr:pic` внутри `oneCellAnchor` / `twoCellAnchor` (ячейка — `from`).
  Связь с медиафайлом идёт через `a:blip/@r:embed` → `drawingN.xml.rels`.
- Фигуры без картинки (`xdr:sp`, `AutoShape`) пропускаются, итог — info-сообщение с ячейками. В образце пустые
  фигуры в A23 и A24 — остатки вставки из браузера.
- `absoluteAnchor` и графики (`graphicFrame`) дают ошибку `image_outside`.
- Принадлежность определяется по ячейке `from`: `A{r}` — вопрос r, ячейка варианта — этот вариант.
  Любая другая ячейка (строка 1, B, C, D, ячейка уровня, лишние ячейки типов 3 и 5) — ошибка `image_outside` (как в DOT).
- До 5 картинок на вопрос (порядок: строка, затем столбец, затем `xdr:cNvPr/@id`). На вариант — одна; вторая даёт ошибку.
- Вариант только с картинкой (пустой текст) допустим. Вопрос только с картинкой (пустой A) допустим.
- Форматы: PNG, JPEG, GIF, WebP; определяются по сигнатуре, а не по расширению. EMF, WMF, SVG и TIFF дают ошибку
  `image_format` с советом «вставьте как PNG»: EMF часто получается при копировании из Word.
- Каждая картинка ≤ 5 МБ, сторона ≤ 8192 px (крейт `imagesize`). Иначе ошибка.
- Одна и та же картинка в нескольких местах загружается один раз (по SHA-256) и связывается со всеми местами.

### 4.6 Лимиты файла

| Что | Предел | Ошибка |
|---|---|---|
| размер файла | 20 МБ | `file_too_large` |
| распакованный объём всего архива / одной части | 200 МБ / 50 МБ, коэффициент сжатия ≤ 100 | `file_unreadable` |
| записей в zip | ≤ 10 000 | `file_unreadable` |
| вопросов | ≤ `MAX_BANK_ITEMS` (1000, Q-2) | `too_many_questions` |
| столбцов вариантов | ≤ 50 (E…BB) | `too_many_options` |
| картинок | ≤ 300 | `too_many_images` |
| ошибок в отчёте | первые 100 + счётчик остальных | — |

Объединённые ячейки в строках вопросов дают предупреждение `merged_cells`: значение есть только в левой верхней.
Скрытые строки и столбцы импортируются, но получают предупреждение `hidden_cells`.

## 5. Соответствие модели Ashyq

### 5.1 Типы вопросов

| DOT | Ashyq | Примечание |
|---|---|---|
| 1 | `choice`, `multiple=false`, `variant=single_choice` | вариантов ≥ 2 (правило готовности), иначе ошибка `too_few_options` |
| 2 | `choice`, `multiple=true`, `variant=multiple_choice` | ≥ 1 правильного, ≥ 2 вариантов |
| 3 | новый `short_answer` | `accepted: [C]`, `case_sensitive: true` |
| 4 | `matching` + расширение (5.2) | левые с правым 0 и лишние правые переносятся без потерь |
| 5 | `open_text` | **отличие**: ручная проверка вместо автозачёта (Q-3); в предпросмотре предупреждение «N вопросов потребуют ручной проверки» |

Проверка новых и расширенных видов (`crates/domain/src/grading/grader.rs`):
- **`short_answer`:**
  - ответ и эталоны обрезаются по краям, внутренние пробелы схлопываются;
  - совпадение с любым из `accepted` даёт полный балл;
  - регистр учитывается при `case_sensitive` (по умолчанию да, как в DOT);
  - если обе строки — числа (`,` или `.` как разделитель), они сравниваются как числа: `"1.0" = "1"`, как нестрогое
    `==` в DOT;
  - частичного балла нет.
- **`matching`:**
  - верно, если каждый левый элемент стоит у своего правого, а элемент с `right = None` не стоит ни у какого;
  - при `partial_credit = false` — всё или ничего (как в DOT); при `true` — доля верно размещённых левых
    (существующая `grade_matching`, `:153`).

Новые proptest-инварианты рядом с существующими: балл в [0, max], полный балл только при полностью верном ответе.

Баллы: у каждого вопроса `max_score = 1` (в DOT все вопросы равны). Итог в процентах идёт по существующему `item_points`
(`grader.rs:80`) среди **выданных** вопросов: при выборке 30 каждый вопрос стоит 100/30.

### 5.2 Изменения модели (`crates/domain/src/assessments/items.rs`)

Все поля новые и опциональные, с `#[serde(default)]`. `schema_version` остаётся 1, старые тела читаются без миграции данных.

```rust
pub enum TextFormat { #[default] Markdown, Plain }

pub struct MediaRef { pub upload_id: Uuid, pub width: u32, pub height: u32, #[serde(default)] pub alt: String }

pub struct ChoiceBody   { /* … */ #[serde(default)] pub prompt_format: TextFormat, #[serde(default)] pub media: Vec<MediaRef> }
pub struct ChoiceOption { /* … */ #[serde(default)] pub media: Option<MediaRef> }
pub struct OpenTextBody { /* … */ #[serde(default)] pub prompt_format: TextFormat, #[serde(default)] pub media: Vec<MediaRef> }
pub struct ShortAnswerBody { prompt, prompt_format, media, accepted: Vec<String>, case_sensitive: bool, explanation }
pub struct MatchingPair { pub left: String, pub right: Option<String>, #[serde(default)] pub left_media: Option<MediaRef>, #[serde(default)] pub right_media: Option<MediaRef> }
pub struct MatchingBody { /* … */ pub pairs: Vec<MatchingPair>, #[serde(default)] pub distractors: Vec<Distractor> } // Distractor { text, media }
```

Тип 4 DOT переводится так:
- левый элемент `k` с парой `k-r`, `r > 0` → `MatchingPair { left, right: Some(правый r) }`;
- левый с `k-0` → `right: None` (студент должен оставить его без пары);
- правые элементы, на которые не ссылается ни один левый, → `distractors`;
- если на один правый ссылаются несколько левых (DOT это допускает), этот правый текст повторяется в нескольких
  `pairs`, а в списке студента показывается один раз.

`right: String` → `Option<String>` читает старые тела без изменений. Проверка «правые различны» (`items.rs:715`)
применяется к множеству уникальных правых и `distractors`.

Студент (`MatchingLearnerBody`, `items.rs:246`):
- правая колонка — уникальные правые и `distractors`, перемешанные;
- у каждого левого есть явный вариант «Без пары» (`right: ""`); невыбранный левый считается неотвеченным,
  «Без пары» — ответом.

- **`prompt_format = plain`** ставится у импортированных вопросов. Текст из Excel не markdown: `List<String>`, `*`,
  `_` и отступы в 4 пробела исказились бы. Plain отображается как текст с `white-space: pre-wrap`, HTML не
  интерпретируется. В редакторе есть действие «Преобразовать в Markdown» (одностороннее, с экранированием).
- **Варианты** всегда plain. Плеер и редактор выводят их с `white-space: pre-wrap`; текст с переводом строки идёт моноширинным
  блоком. Сейчас `choice-item.tsx:45,66` схлопывает многострочный код из A28 и E31 в одну строку.
- **Готовность** (`items.rs:569-719`):
  - промпт можно оставить пустым, если есть `media`;
  - вариант можно оставить пустым, если есть `media`;
  - совпадение вариантов проверяется точным сравнением после trim (4.4 п. 6), это касается и `matching` (`:710,715`);
  - `media.upload_id` должен ссылаться на `uploads` с назначением `assessment-image` из того же курса.
- **`redact_for_learner`** (`items.rs:295`) оставляет `media` и `distractors`, а `accepted` убирает.
- Ограничение «≤ 200 вопросов» (`MAX_ITEMS`) остаётся для тестов без выборки. Если `draw_count` задан, действует
  `MAX_BANK_ITEMS = 1000` (Q-2). Выдавать за попытку можно ≤ 200 вопросов.

### 5.3 Политика теста из файла и по умолчанию

| Поле | Значение при импорте |
|---|---|
| `kind` | выбирает преподаватель: «Тест» (`quiz`) или «Экзамен» (`exam`) |
| `max_attempts`, `time_limit_seconds`, `draw_count` | из C1, D1, E1 (4.1) |
| `randomize_questions`, `randomize_options` | `true` (DOT перемешивает всегда) |
| `partial_credit` | `false` (DOT: тип 2 «всё или ничего»), можно включить (Q-4) |
| `passing_score` | 50 (`Test::RATING_REQUIREMENT` DOT) |
| анти-списывание | `exam`: все флаги включены (в DOT итоговый тест принудительно включает всё); `quiz`: пресет `AssessmentKind` |
| `grade_release_mode` | пресет вида; правильные ответы студенту не показываются (как в DOT) |
| `lifecycle` | `draft`: публикует преподаватель после проверки |

Все поля можно изменить в предпросмотре до фиксации. В режиме «добавить вопросы» политика из файла по умолчанию
не применяется (флажок «Применить настройки из файла»).

## 6. Выборка вопросов (банк)

### 6.1 Политика

Новые поля в `assessments`:
- `draw_count int NULL`: `NULL` — все вопросы, как сейчас;
- `draw_strata jsonb NULL`: `[{group: "1", count: 9}, …]`.

Новое поле `assessment_items.draw_group text NULL` (уровень DOT строкой: «1», «101»…). Уровни 1/2/3 заодно
записываются в `difficulty` (`easy`/`medium`/`hard`); 101–202 туда не попадают.

Проверки при сохранении политики и при публикации:
- `1 ≤ draw_count ≤ min(200, число готовых вопросов)`;
- `Σ strata.count ≤ draw_count`;
- `strata.count ≤` числа вопросов группы.

### 6.2 Алгоритм выдачи

1. При старте попытки (`SubmissionsService::start`, `grading/submissions.rs:604`) генерируется `selection_seed`
   (случайный u64, OsRng). Он и упорядоченный список `selected_item_ids` пишутся в `submissions` в той же транзакции.
2. Выбор (Fisher–Yates на существующем splitmix64, `items.rs:271`, семя `selection_seed`, исходный порядок — `position`):
   1. для каждой квоты из `draw_strata` по порядку берутся первые `count` перемешанных готовых вопросов её группы;
   2. остаток до `draw_count` — первые из перемешанных невыбранных готовых вопросов любых групп;
   3. итог перемешивается при `randomize_questions = true`, иначе сортируется по `position`.
3. Порядок вариантов: семя `hash(selection_seed, item_id)`. У каждой попытки свой порядок, как в DOT.
   Без выборки остаётся текущее детерминированное `shuffle_seed(user, id)`.
4. Повторный вход в черновик возвращает ту же выборку. Новая попытка — новую.
5. `GET` для студента (`AssessmentsService::get`, `service.rs:887`) при заданном `draw_count` отдаёт только вопросы
   из `selected_item_ids` открытого черновика. До старта отдаёт политику и число вопросов, без тел.
6. Сохранение черновика и сдача отклоняют ответы на невыданные вопросы (`422 item_not_in_attempt`).
7. Снимок при сдаче (`items_snapshot`, `assessment_versions`) содержит только выданные вопросы. Поэтому `grade_quiz`,
   перепроверка, разбор результатов и выгрузки работают без изменений.
8. Если вопрос удалён или стал неготовым во время открытой попытки, он выпадает из выборки и знаменатель уменьшается.
   Добор не делается (детерминированность важнее). Правка опубликованного теста с попытками и так ограничена
   `ensure_editable` (`service.rs:41`).
9. Предпросмотр преподавателем (`preview` submissions) использует тот же механизм.
10. Свидетельства мастерства (AI-FIRST §3.1) и статистика по вопросам считаются только по выданным вопросам:
    знаменатель — «сколько раз выдан», а не «сколько попыток».

### 6.3 Уровни сложности

При импорте с `F1 = 1` квоты считаются по формуле DOT (BR-TST-10) для L = `draw_count`:
- уровни 1/2/3 — ⌊0,3L⌋/⌊0,4L⌋/⌊0,3L⌋;
- уровни 101/102 — ⌊L/2⌋ каждый;
- уровни 201/202 — ⌊2L/3⌋/⌊L/3⌋.

Квоты применяются в этом порядке и обрезаются до L и до размера групп. Результат пишется в `draw_strata` как явные
числа и показывается в предпросмотре для правки (пример: L = 30 → 9/12/9).

**Отличие от DOT.** Недобор DOT перемешивает весь банк и теряет пропорции. Здесь недобор добирается случайно из
невыбранных вопросов любых групп, а уже выбранные остаются.

## 7. Процесс импорта

```
загрузка файла ──► POST …/assessment-imports ──(разбор в запросе)──► ready | invalid
                                                                       │      ▲
                                    PATCH {unescape_newlines} ─────────┘──────┘ (повторный разбор того же файла)
ready ──► POST commit ──► committed (result.assessment_id)        ready|invalid ──► DELETE (запись удаляется)
незафиксированный через 24 ч, зафиксированный через 30 дней ──► удаляется заданием uploads:reap
```

1. Клиент загружает файл через существующий поток uploads с назначением `assessment-import`: приватный бакет,
   ≤ 20 МБ, MIME `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`, права автора курса.
2. `POST /courses/{course_id}/assessment-imports {upload_id, file_name, unescape_newlines}` в одной транзакции:
   - забирает upload (`claim_upload`: только свой, finalized, нужного назначения);
   - читает файл из хранилища и разбирает его в `spawn_blocking` (раздел 4). Задания и опроса нет: книга
     на 1000 вопросов разбирается быстрее секунды, ответ уже содержит результат;
   - кладёт картинки в хранилище как uploads `assessment-image` (статус `finalized`, часы удаления на 24 ч).
     Пока импорт жив, их держит `assessment_imports.image_upload_ids` (`upload_referenced`);
   - пишет план (`parsed`), `issues`, `status`.
3. `PATCH` перечитывает тот же файл с другим режимом `\n`. Картинки того же файла переиспользуются, не дублируются.
4. `POST …/commit` выполняется одной транзакцией:
   - блокирует импорт `FOR UPDATE`; `invalid` → 409 `assessment-import-invalid`;
   - `new`: создаёт активность и тест (`AssessmentsService::create_in`) в главе того же курса;
     `replace` / `append`: блокирует целевой тест, он должен быть того же курса и редактируемым (`ensure_editable`);
   - пачкой вставляет вопросы (`insert_imported_items`, `UNNEST WITH ORDINALITY`) с `source_file` и `source_row`;
   - снимает часы удаления с картинок (`uploads::hold`); ссылки вопрос → картинка ведёт триггер
     `assessment_items_upload_ids` (таблица `assessment_item_uploads`);
   - один раз увеличивает версию содержимого и пишет событие аудита `imported-from-xlsx`;
   - ставит `status = committed`.

   Повторный `commit` того же импорта возвращает тот же результат (и ещё `Idempotency-Key`).
5. Режимы: `new` — в главе `chapter_id` (вид `exam` по умолчанию); `replace` — все вопросы теста заменяются;
   `append` — дописываются в конец. Тест с попытками не редактируется: для него создаётся новый тест.
6. `DELETE` удаляет запись и отпускает картинки (часы удаления 24 ч).

Почему разбор на сервере, а не в браузере (SheetJS + существующий `POST …/items`):
- свободные JS-библиотеки не отдают привязку картинок к ячейкам;
- 64 отдельных запроса не атомарны;
- файл всё равно нужно проверять на сервере.

Ограничения и защита:
- создание импорта — не больше 10 в минуту на пользователя (Redis, `assessment_import_rl:{user}`), сверх — 429
  `rate-limited` с `Retry-After`;
- `commit` в `replace` / `append` принимает `If-Match` с версией целевого теста, которую видел преподаватель;
  тест успел измениться — 412 (web-2 шлёт заголовок всегда, без него сравнения нет);
- переключатель «Сопоставить с концептами (ИИ)» в мастере: после успешного `commit` web-2 вызывает
  `POST /assessments/{id}/concepts/suggest` (новый тест — по его главе, существующий — по всему курсу); ошибка ИИ
  показывается тостом и не отменяет импорт.

`assessment-export-empty` (422, ни один вопрос не ложится в формат). Ответ на невыданный вопрос отклоняется как
ответ на чужой вопрос (`validation-failed`). Сообщения разбора — коды с параметрами (раздел 10); текст собирает
клиент на трёх языках.

### 8.1 Выгрузка в xlsx

Цель: преподаватель может выгрузить тест, поправить его в Excel и загрузить обратно (режим «Заменить»). Тест,
созданный в редакторе Ashyq, тоже выгружается, если его вопросы есть в формате DOT.

- Пишется крейтом `rust_xlsxwriter`: картинки, форматы чисел, комментарии. Для тестов ридера он уже нужен как
  dev-dependency (раздел 14), здесь становится обычной зависимостью `crates/domain`.
- **Лист `Test`** (активный):
  - строка 1 — A1 = название, B1 = 0, C1/D1/E1/F1 из политики;
  - подписи — числовыми форматами, как в DOT: `0" [попыток]"`, `0" [минут]"`, `0" [вопросов в попытке]"`;
  - комментарий в F1 описывает уровни.
- **Строки вопросов** в порядке `position`, по правилам 4.2:
  - тип 1/2 — C = `1;3`;
  - тип 3 — C = первый из `accepted` (остальные → лист «Пропущено» как предупреждение);
  - тип 4 — D = `L;R`, C = `1-2;2-0`, уровень в E;
  - тип 5 — C пусто;
  - уровень = `draw_group`, если F1 = 1;
  - варианты и эталоны пишутся как текстовые ячейки, поэтому при обратной загрузке «310» и «310.0» не меняются.
- **Картинки** привязываются `oneCellAnchor` к своей ячейке. Высота строки подгоняется под картинку (≤ 409 pt;
  крупнее — масштаб с сохранением пропорций).
- **Текст.**
  - `plain` пишется как есть;
  - `markdown` пишется исходным текстом, а ячейка получает предупреждение в листе «Пропущено» («форматирование
    Markdown не переносится»);
  - переводы строк остаются настоящими переводами (не `\n`), поэтому обратная загрузка в режиме `dot` их не меняет.
- **Не переносится** (вид `form`, `code`; `explanation`; `max_score ≠ 1`; квоты сверх формулы DOT):
  - такие вопросы и поля перечисляются на втором листе «Пропущено» (строка, вопрос, причина);
  - активным остаётся `Test`, поэтому обратная загрузка его не читает;
  - если пропущены все вопросы — 422 `assessment_export_empty`.
- **Круговой тест:** выгрузка → загрузка → те же тела вопросов (без учёта id), та же политика и те же картинки (по SHA-256).

### 11.1 web-2: новая фича `assessment-import`

Создаётся через `just new feature assessment-import`, вместе со SPEC.md и B-id. Маршруты вносятся в `docs/web/ROUTES.md`.

**Точки входа:**
1. Студия курса, глава → «Добавить» → «Тест из Excel» (`add-item-menu` уровня главы).
2. Конструктор существующего теста (`features/assessments/ui/builder-page.tsx`) → меню → «Загрузить вопросы из Excel»
   (замена или добавление).

**Шаг 1. Файл.**
- Перетаскивание или выбор файла, только `.xlsx`. Лимит берётся из `upload-policy.gen.ts`.
- Ссылка «Скачать шаблон»: `apps/web-2/public/templates/test-template.xlsx` с примером каждого типа и листом
  «Инструкция»; активный лист — пример.
- Свёрнутая шпаргалка по формату (таблицы 4.1 и 4.2).

**Шаг 2. Разбор.**
- Индикатор, опрос `GET` через TanStack Query `refetchInterval` до терминального статуса.

**Шаг 3. Предпросмотр.** Сверху вниз:
1. Шапка:
   - имя файла и лист;
   - название (поле ввода);
   - счётчики «64 вопроса · 64 с одним ответом · 6 изображений»;
   - бейджи «Ошибок N», «Предупреждений M».
2. Панель сообщений: ошибки, затем предупреждения, затем info; группировка по коду. У каждого сообщения есть ячейка,
   по клику список прокручивается к карточке вопроса. Кнопка «Скопировать список» нужна, чтобы исправлять файл рядом.
3. Настройки:
   - вид («Тест» / «Экзамен»);
   - попыток (0 = без ограничений);
   - минут (0 = без лимита);
   - «Вопросов в попытке: [30] из 64»;
   - перемешивание;
   - частичные баллы;
   - проходной балл;
   - анти-списывание (флаги из существующего редактора политики, переиспользуется);
   - глава (для `new`) или режим «заменить / добавить» (для конструктора);
   - переключатель «Не преобразовывать `\n`» (→ `PATCH`, повторный разбор).
4. Список вопросов (виртуализированный, до 1000):
   - строка в файле, тип, промпт в том же виде, что в плеере;
   - миниатюры картинок (клик — увеличение);
   - варианты с отметкой ✓ у правильных;
   - сообщения этой строки у карточки.
5. Действия:
   - «Создать тест» / «Заменить вопросы» / «Добавить вопросы» — недоступны при ошибках, с подсказкой «Исправьте файл и загрузите снова»;
   - «Загрузить другой файл»;
   - «Отменить» (`DELETE`).

**Шаг 4.** Переход в конструктор созданного теста, тост «Импортировано 64 вопроса».

**Изменения в конструкторе и редакторе вопроса:**
- в политике появляется «Вопросов в попытке» и квоты по группам, а готовность требует ≥ `draw_count` готовых вопросов;
- в редакторе вопроса: переключатель формата текста plain/markdown, добавление, замена и удаление картинки промпта
  и варианта (назначение `assessment-image`, `useUpload`);
- метка «Из Java_EXAM_2026_2.xlsx, строка 29» (`source_row`).

**Изменения в плеере (`features/attempt`):**
- варианты с `whitespace-pre-wrap`, многострочные — моноширинным блоком;
- plain-промпт;
- картинки через `/api/v2/assessments/{id}/media/{upload_id}`: `loading="lazy"`, `alt` «Изображение к вопросу N», клик — увеличение
  в диалоге (кроме картинок в вариантах ответа: там клик выбирает вариант); не загрузилась — два автоматических повтора,
  затем заглушка с кнопкой «Повторить»;
- навигатор и счётчик показывают выданные вопросы;
- `policy-summary` пишет «30 вопросов» студенту и «30 из банка 64» преподавателю;
- разбор результатов показывает выданные вопросы.

## 12. Безопасность

1. **zip/xml.**
   - Лимиты 4.6 проверяются до распаковки по заголовкам и во время потокового чтения.
   - Файлы на диск не извлекаются.
   - `DOCTYPE` и сущности отклоняются; quick-xml внешних сущностей не раскрывает.
2. **Картинки.**
   - Проверка сигнатуры и размеров; `Content-Type` выставляет сервер.
   - Отдаются с `X-Content-Type-Options: nosniff` и `Content-Disposition: inline`.
   - SVG и EMF запрещены.
3. **Текст.** Plain выводится как текст. Markdown идёт через существующий санитайзер. В DOT была XSS (D-08: `|raw`):
   здесь этого пути нет.
4. **Ключ ответов.**
   - `parsed` с правильными ответами отдаётся только авторам курса.
   - Студенческий `GET` идёт через `redact_for_learner`.
   - Имена и метаданные картинок не выдают правильный вариант: ключи `assessment-image/{uuidv7}`, без `00_Image_n`.
5. **Картинки экзамена приватны** (Q-5): приватный бакет, выдача через `assessment-media` с проверкой права чтения теста.
   Невыданные вопросы недоступны через `GET`. Картинку можно получить только по её UUID.
6. **Конфиденциальность экзаменов.**
   - Исходный файл хранится в приватном бакете ограниченное время.
   - В логи и трейсы не пишется текст вопросов: только id, коды и счётчики.
   - Фикстуры тестов синтетические: реальные экзамены, включая `Java_EXAM_2026_2.xlsx`, в репозиторий не попадают.
7. **Изоляция.**
   - Разбор идёт в задании, а не в HTTP-запросе: таймаут 60 с, ошибка → `failed`, без повторов по кругу (лимит попыток задания 3).
   - Паника ридера ловится и превращается в `failed`.

## 13. Производительность

- Файл 20 МБ, 1000 вопросов, 300 картинок: разбор ≤ 15 с, фиксация ≤ 5 с (пачечная вставка).
- Студенческий `GET` при выборке отдаёт ≤ 200 вопросов, а не весь банк.
- Опрос раз в секунду, пока идёт разбор. `AssessmentImport` с 1000 вопросами ≈ 1–2 МБ JSON, поэтому `items`
  отдаются только в статусах `ready` и `invalid`.

## 14. Проверки

**Сервер:**
- **Ридер** (`crates/domain/src/assessments/import/`).
  - Модульные тесты на фикстурах, которые строит тест через `rust_xlsxwriter` (dev-dependency):
    - shared/inline/rich строки, числа (`310` против `"310.0"`, `0.1`, `1E-7`), даты, boolean, ошибки, формулы;
    - объединённые и скрытые ячейки, `\r\n`, NBSP;
    - картинки one/two/absolute-anchor, фигуры, одна картинка в двух местах, EMF/SVG, `vm=` (в ячейке), zip-бомба,
      `DOCTYPE`, неактивный лист, `date1904`.
  - Двоичные фикстуры, сохранённые из LibreOffice Calc, Google Sheets и WPS Office: в них отличаются inlineStr,
    стили и anchors.
- **Разбор формата.** Тест на каждый код из раздела 10 с проверкой ячейки.
- **Свойства (proptest):**
  - выборка выдаёт ровно `min(draw_count, готовых)` вопросов без повторов и детерминирована по семени;
  - квоты соблюдаются, если вопросов хватает;
  - существующие инварианты `grader.rs` остаются зелёными, новые инварианты есть для `short_answer` и `matching`
    с `right = None` и `distractors`.
- **Проверка ответов:**
  - `short_answer` — регистр, числа (`1.0`/`1`/`1,0`), пробелы, несколько эталонов;
  - `matching` — левый без пары, лишние правые, один правый у двух левых.
- **Квоты** 6.3 — таблица на L = 1…300 сверяется с формулой DOT BR-TST-10.
- **Выгрузка:**
  - круговой тест на фикстуре со всеми типами, уровнями и картинками даёт тождественный результат;
  - вопрос вида `form` попадает на лист «Пропущено»;
  - тест только из таких вопросов → 422.
- **API** (`#[ab_testdb::test]`, `crates/api/tests/assessment_imports_flow.rs` через `just new endpoint`):
  - полный путь upload → parse → commit для трёх режимов;
  - повторный commit;
  - истёкший импорт;
  - чужой курс → 403;
  - студент → 403;
  - `replace` теста с попытками → 409;
  - попытка с выборкой: ответ на невыданный вопрос → 422;
  - снимок содержит только выданные;
  - реапер не трогает связанные картинки.
- `permission_matrix.rs`, `rbac_sweep.rs`, снимки OpenAPI и реестра кодов.

**web-2:**
- B-id в SPEC.md каждый покрыт тестом.
- Браузерные тесты предпросмотра (ошибки, переход к ячейке, блокировка кнопки).
- E2E (`just e2e web2 --changed`): загрузка синтетической фикстуры → предпросмотр → создание. Затем студент проходит
  попытку: видит `draw_count` вопросов, таймер, картинки, многострочный вариант.

**Шаблон.** Тест импортирует `public/templates/test-template.xlsx` без ошибок.

## 15. Приёмка

### 15.1 Полный формат (синтетический файл, автоматически)

Фикстура `full-format.xlsx` собирается тестом и содержит:
- типы 1–5;
- тип 4 с `L ≠ R`, парой `k-0` и общим правым;
- уровни 1/2/3 при `F1 = 1` и `E1 = 30` на банке 60 вопросов (по 20 на уровень);
- картинки в A и в варианте, поверх ячейки и «в ячейке».

Ожидается:
- разбор без ошибок;
- квоты 9/12/9;
- в 100 попытках каждая содержит ровно 9/12/9 по уровням;
- `short_answer` и `matching` проверяются по 5.1;
- выгрузка и обратная загрузка тождественны.

### 15.2 `Java_EXAM_2026_2.xlsx` (вручную, локально)

1. Разбор без ошибок (проверено 2026-11-13: `DOT_SAMPLE_XLSX=<путь> cargo test -p ab-api --test assessment_imports_flow -- --ignored`, затем вручную на стенде). Предпросмотр:
   - название из A1;
   - 64 вопроса (строки 2–65), все с одним ответом;
   - 6 изображений у вопросов в строках 29–34;
   - попыток 1, время 55 мин, вопросов в попытке 30, уровни выключены.
2. Сообщения ровно такие:
   - info `unescaped_newlines` (A53, A54, A55, A62);
   - info `trimmed` (E5, F5, G5);
   - info `shapes_skipped` (A23, A24);
   - warning `service_cell` не выдаётся (B1 = 0);
   - warning `suspicious_escape` (A53, A54);
   - warning `duplicate_question` (строка 60 = строка 51).
   Пары 29/30, 52/61 и 55/62 дубликатами не считаются: у 29/30 разные картинки, у остальных разный текст.
3. A32 проходит готовность: варианты различаются регистром. E34 «310» и F34 «310.0» — два разных варианта.
4. Варианты с кодом в строках 28 и 31 в плеере многострочные и моноширинные.
5. «Создать как экзамен» даёт черновик экзамена:
   - 64 вопроса, `draw_count = 30`, `max_attempts = 1`, `time_limit_seconds = 3300`;
   - все флаги анти-списывания включены, `partial_credit = false`, проходной балл 50.
6. Студент:
   - получает 30 вопросов, таймер 55:00, картинки видны;
   - второй попытки нет;
   - при 30 правильных из 30 — 100 %, при 15 из 30 — 50 % и «зачтено»;
   - у второго студента другой набор вопросов.
7. Повторная загрузка того же файла в режиме «Заменить» до публикации заменяет 64 вопроса. После первой попытки
   студента предлагается только «Создать новый тест».

## 17. Решения

Q-1 и объём решены владельцем 2026-11-13. Остальные приняты по умолчанию в тот же день: владелец поручил подготовить
всё полностью. Любое из них можно пересмотреть до начала соответствующего шага работ; тогда меняется раздел, указанный
в скобках.

- **Q-1 (владелец).** Интерфейс только web-2, прод на нём полностью (11.2).
- **Объём (владелец).** Формат DOT целиком, включая выгрузку; срок — ближайшая сессия (3).
- **Q-2.** `MAX_BANK_ITEMS = 1000` для тестов с выборкой; без выборки остаётся 200, за попытку выдаётся ≤ 200 (5.2).
  Банки DOT бывают по 300–500 вопросов.
- **Q-3.** Тип 5 — ручная проверка, а не автозачёт любого ответа (5.1). Автозачёт делает вопрос бессмысленным.
- **Q-4.** Частичные баллы за тип 2 и тип 4 по умолчанию выключены, как в DOT; преподаватель включает в предпросмотре (5.3).
- **Q-5.** Картинки приватные, выдаются через `assessment-media` (12.5). Публичные ссылки позволили бы раздать
  картинки экзамена заранее.
- **Q-6.** `.xls` не поддерживается, сообщение с советом пересохранить (4.3). `calamine` читает только значения,
  без картинок.
- **Q-7.** Исходный файл хранится 30 дней после фиксации, событие аудита — бессрочно (9).
- **Q-8.** C1 > 10 ограничивается до 10 с предупреждением; `MAX_ATTEMPTS` не меняется (4.1).

## 18. Сознательные отличия от DOT

| DOT | Ashyq | Почему |
|---|---|---|
| загрузка сразу пишет тест | предпросмотр и подтверждение | ошибки видны до создания, настройки правятся |

# Модернизация, этап 1: ТЗ и техническая архитектура

Статус: утверждено владельцем 2026-10-02; репозиторная часть реализована 2026-10-03 (см. `docs/INFRA.md`),
переключение прода не выполнено (см. `docs/RUNBOOK.md`, раздел 1). Отклонения от текста - в `docs/DECISIONS.md`.
Область: всё в репозитории и на прод-хосте, **кроме** `apps/server` и `apps/web`.
Этап 2 (перепись `apps/web` на React + TanStack Start + Paraglide + переосмысление архитектуры) здесь не проектируется;
для него в разделе 6 зафиксирован только контракт, который этап 1 обязан подготовить.

## 1. Цель

После cutover 2026-09-30 сервер новый, а всё вокруг него - слой за слоем наросшее наследство
форка LearnHouse, Python-эпохи и самого cutover. Этап 1 переписывает этот слой так, чтобы:

1. Данные нельзя было потерять одним отказом диска или одной ошибкой оператора.
2. Стек описан **один раз** и одинаково поднимается в prod, dev и CI одной командой, без ручных шагов.
3. В прод попадают только образы, собранные и проверенные в CI; откат - одна команда.
4. Ни один контейнер не получает секретов и сетевого доступа сверх необходимого.
5. Инфраструктура ничего не знает о фреймворке веб-приложения: на этапе 2 образ `web`
   заменяется без единой правки nginx, compose и CI-каркаса.
6. В репозитории нет мусора, дублей и двух источников правды.

## 2. Границы

**В области этапа:** `docker-compose*.yml`, `extra/`, `judge0.conf`, `.github/`, корневые
`package.json` / `bun.lock` / `vite.config.ts` / `.env.example` / dot-файлы, `docs/`, `README.md`,
`AGENTS.md`, `QUESTIONS.md`, `.agents/`, `.claude/`, `.vscode/`, `temp-restore/`, конфигурация
прод-хоста (каталог деплоя, `.env`, certbot-hook, cron/timers).

**Если потребуется то можно менять:** любой код и конфиг внутри `apps/server/**` и `apps/web/**` и вообще что угодно.

## 4. Требования

### 4.1 Функциональные

- **R-01 Одно определение стека.** Каждый сервис описан в одном месте; prod, dev и CI - это наборы
  оверрайдов, а не копии. Версии образов закреплены (тег + digest) и одинаковы во всех средах.
- **R-02 Bootstrap без ручных шагов.** `just bootstrap` на пустом хосте идемпотентно создаёт роли и БД,
  бакеты, политику, CORS, права на том Zitadel, получает PAT и настраивает Judge0.
  Повторный запуск ничего не меняет.
- **R-03 Dev-паритет.** `just dev-up` поднимает зависимости сервера на Windows + podman и на
  Linux + docker. Подкоманды из `apps/server/AGENTS.md` заменяются этой одной.
- **R-04 Релиз из реестра.** CI на зелёном коммите `main` публикует `ashyq-server:<sha>` и
  `ashyq-web:<sha>`. Прод-хост только скачивает. Деплой коммита без образа в реестре невозможен.
- **R-05 Откат одной командой** на предыдущий sha, если между версиями не было миграций;
  иначе - документированное восстановление из pre-deploy дампа.
- **R-06 Бэкап:** ежесуточно, без остановки сервисов, логический дамп Postgres, шифрование,
  копия вне хоста, включая файлы секретов.
- **R-07 Восстановление:** один скрипт поднимает стек из архива на чистой машине;
  `just restore-drill` проверяет последний архив в изолированном compose-проекте.
- **R-08 Наименьшие привилегии:** контейнер получает только свои переменные; приложение и Zitadel
  ходят в Postgres не суперпользователем; Redis и Judge0 требуют аутентификацию; Judge0 не имеет
  сетевого пути к данным приложения.
- **R-09 Веб-агностичный edge:** в nginx и compose нет ни одного пути или переменной, специфичных
  для Next.js, кроме одного явно помеченного блока сборочных аргументов образа `web`.
- **R-10 Гейты на всё:** любое изменение инфраструктуры проходит статические проверки и smoke-подъём
  полного стека в CI.
- **R-11 Наблюдаемость-минимум:** внешний uptime-чек, dead-man-сигнал от бэкапа, предупреждение о
  заполнении диска, сроке сертификата и сроке PAT.
- **R-12 Одна точка входа:** корневой `justfile`. Прод-хосту нужны только docker, git, just.

## 5. Целевая архитектура

### 5.1 Раскладка репозитория

```
/
|- compose.yaml            общие сервисы: db, redis, zitadel, rustfs, judge0-*, init-задачи
|- compose.prod.yaml       nginx, web, server, worker, backup; лимиты, логирование, сети
|- compose.dev.yaml        публикация портов на 127.0.0.1, dev-значения
|- justfile                единственная точка входа
|- infra/
|  |- nginx/               nginx.conf.template, routes.conf, security-headers.conf
|  |- postgres/            init.sql (идемпотентные роли и БД)
|  |- judge0/              judge0.conf (только не-дефолтные, не-секретные значения)
|  |- storage/             cors.json.template, public-policy.json
|  |- env/                 prod.env.example, server.env.example, dev.env (коммитится)
|  `- scripts/             preflight, bootstrap, deploy, rollback, smoke,
|                          restore, restore-drill, renew-certificate, host-inventory
|- docs/
`- .github/workflows/      server.yaml, web.yaml, infra.yaml
```

Compose-файлы остаются в корне: каталог проекта не меняется, `just services` в сервере правится
одной строкой. `extra/`, корневой `judge0.conf`, `extra/Dockerfile.db` исчезают.

Выбор файлов - через `COMPOSE_FILE` в рецептах just, не руками:
prod = `compose.yaml:compose.prod.yaml`, dev = `compose.yaml:compose.dev.yaml`.

**Жёсткое ограничение.** Имя прод-проекта закрепляется явно: `COMPOSE_PROJECT_NAME=openu-prod`
в прод-env. Тома не переименовываются. `preflight` падает, если ожидаемый том
`${COMPOSE_PROJECT_NAME}_postgres_data` не существует на хосте, где уже был деплой.

### 5.2 Сервисы, сети, зоны доверия

```
                 80/443
                   |
   edge-net:    [nginx] ----------------------------.
                 |    |                              |
   app-net:    [web] [server] [worker]            [rustfs]
                        |  |  \                      |
   data-net:        [db] [redis] [zitadel] ----------'
                        |
   exec-net        [judge0-server] [judge0-workers] [judge0-db] [judge0-redis]
   (internal):          ^
                        '-- только server/worker
```

| Сеть                  | Участники                                                       | Правило                                        |
| --------------------- | --------------------------------------------------------------- | ---------------------------------------------- |
| `edge-net`            | nginx, web, server, rustfs                                      | единственная сеть, куда смотрит nginx          |
| `data-net` (internal) | server, worker, zitadel, db, redis, rustfs, init-задачи, backup | web сюда не входит                             |
| `exec-net` (internal) | server, worker, judge0-\*                                       | Judge0 не имеет пути к `db`/`redis` приложения |

Изменения относительно текущего состояния:

- **Judge0 получает собственные `judge0-db` и `judge0-redis`** в `exec-net`. Данные Judge0 эфемерны,
  в бэкап не входят, перенос не нужен: после переключения выполняется идемпотентный
  `ashyq admin judge0-tune`. Альтернатива "отдельная БД в общем кластере" отклонена: привилегированная
  песочница остаётся с сетевым путём к прод-данным.
- **Judge0 требует токен:** `AUTHN_TOKEN` на стороне Judge0, `AB__JUDGE0__API_KEY` на стороне сервера.
- **Redis требует пароль** (`--requirepass`), URL сервера несёт его.
- **Zitadel разделён** на одноразовый `zitadel-init` (с admin-учёткой Postgres) и постоянный сервис
  на `start-from-setup` без неё.
- **Образ БД один:** `pgvector/pgvector:<версия>-pg18-trixie` по digest во всех средах. Обязательно
  trixie (glibc/collation прод-кластера). До переключения проверить на drill: версия расширения
  в образе >= установленной в БД.
- **Healthcheck'и** берутся из образов приложений (они там уже есть); compose их не дублирует.
- **Логирование:** общий якорь `x-logging` (json-file, `max-size: 10m`, `max-file: 5`) на всех сервисах.
- Хак `extra_hosts: host-gateway` остаётся: сервер подписывает S3-URL публичным хостом и ходит
  в хранилище через него же. Это свойство сервера, а не инфраструктуры; зафиксировано в `INFRA.md`.

### 5.3 Postgres: роли и базы

| База              | Владелец                                       | Кто подключается                                          |
| ----------------- | ---------------------------------------------- | --------------------------------------------------------- |
| `ashyq`           | `ashyq` (не суперпользователь)                 | server, worker, server-migrate                            |
| `zitadel`         | `zitadel`                                      | zitadel                                                   |
| `openu` (легаси)  | -                                              | никто; архивируется и удаляется в конце этапа (вопрос Q5) |
| суперпользователь | `openu` в проде, `postgres` в новых установках | только `db-init`, `zitadel-init`, бэкап                   |

`infra/postgres/init.sql` идемпотентен и выполняется одноразовой задачей `db-init` во всех средах
(`docker-entrypoint-initdb.d` не годится: на существующем томе не запускается).

Передача владения объектами `ashyq` от суперпользователя роли `ashyq` - рискованная операция
(`REASSIGN OWNED` от bootstrap-суперпользователя запрещён, нужен пообъектный `ALTER ... OWNER`).
Выполняется только после успешной репетиции на drill-стеке с полным прогоном тестов сервера.

### 5.4 Секреты и конфигурация

На хосте два файла, оба `chmod 600`, оба вне git:

| Файл         | Содержимое                                                                                                             | Кто читает                                  |
| ------------ | ---------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| `.env`       | домен, `IMAGE_TAG`, `COMPOSE_PROJECT_NAME`, инфраструктурные секреты (Postgres, Zitadel, RustFS, Redis, Judge0, бэкап) | только compose для подстановки              |
| `server.env` | только `AB__*`: URL БД, PAT, ключи AI/Resend/Google, OTLP                                                              | `env_file` у server, worker, server-migrate |

- У `web` только явный список `environment:`. `env_file: .env` не остаётся ни у одного сервиса.
- `preflight`: `compose config -q`, отсутствие плейсхолдеров `CHANGE_ME`, длина masterkey,
  срок `ZITADEL_PAT_EXPIRATION` > 30 дней, отсутствие неизвестных `PLATFORM_*` (F#10).
- Dev: коммитится `infra/env/dev.env` с несекретными значениями - единственный источник для
  dev-compose, CI и примеров в `apps/*/.env.example`. Корневой `.env` на dev-машине удаляется.
- Оба прод-файла входят в шифрованный бэкап (закрывает A-04).
- Хранилище секретов в git (sops/age) не вводим: один хост, один владелец.
  Пересмотреть при появлении второго окружения.

### 5.5 Edge

`infra/nginx/routes.conf` целиком:

| Location        | Назначение                           | Особенности                                                     |
| --------------- | ------------------------------------ | --------------------------------------------------------------- | --------------------- |
| `/api/v2/auth`  | server                               | `auth_limit` 10 r/s                                             |
| `/api/v2`       | server                               | `api_limit` 30 r/s, `proxy_buffering off`, таймауты 300 с (SSE) |
| `/content/`     | rustfs, анонимное чтение `ab-public` | кэш 7 дней, immutable                                           |
| `~ ^/(ab-public | ab-private)/`                        | rustfs, presigned как есть                                      | 500M, без буферизации |
| `/`             | web                                  | кэшируется только то, что апстрим пометил `immutable`           |

- **Никаких путей фреймворка.** Статика кэшируется по заголовку апстрима:
  `map $upstream_http_cache_control $skip_cache { default 1; ~immutable 0; }` +
  `proxy_no_cache`/`proxy_cache_bypass`. Next уже отдаёт `immutable` на `/_next/static`,
  так что поведение сохраняется, а старые чанки переживают деплой (как и сейчас).
- Заголовки безопасности - один сниппет `security-headers.conf`, подключаемый в каждом location
  с собственным `add_header`. CSP остаётся за веб-приложением (нужен nonce) - требование к этапу 2.
- `server web:3000 resolve;` + `zone` в upstream (nginx >= 1.27.3): пересоздание контейнера
  не требует reload. Проверить на smoke; если не работает на выбранной версии - оставить reload в `deploy.sh`.
- `set_real_ip_from` - только `${TRUSTED_PROXY_CIDR}`; пустое значение = не доверять никому.
- `global_limit` удаляется. Шим Google callback v1 удаляется после действия владельца (Q7).
- Access-лог в JSON с `request_id` в stdout.
- TLS: `/etc/letsencrypt` монтируется в nginx read-only; `renew-certificate.sh` сводится к
  `docker compose exec nginx nginx -s reload` без хардкода путей и имён. Каталог `./certs` исчезает.
- Замена nginx на Caddy отклонена: rate limiting и proxy cache там плагинами.

### 5.6 Bootstrap

Одноразовые сервисы в `compose.yaml`, связанные `depends_on: service_completed_successfully`:

| Задача         | Действие                                                                         |
| -------------- | -------------------------------------------------------------------------------- |
| `volume-init`  | права на том `zitadel_machinekey` (uid 1000, 0700)                               |
| `db-init`      | `init.sql`: роли, базы                                                           |
| `zitadel-init` | `zitadel init`                                                                   |
| `storage-init` | бакеты `ab-public`/`ab-private`, public-read политика, CORS из шаблона с доменом |

`infra/scripts/bootstrap.sh` поверх них: читает `pat.txt` из тома и дописывает `AB__ZITADEL__PAT`
в `server.env`, если его там нет; запускает `server-migrate`; запускает `judge0-tune`.

### 5.7 Сборка, релиз, откат

```
push main -> гейты server/web/infra -> build+push ghcr.io/meirbek-dev/ashyq-{server,web}:<sha>
                                                           |
хост: git pull && just deploy  ->  preflight -> pull -> [миграции? pg_dump] -> migrate
                                   -> up -d --wait -> smoke через nginx -> запись sha в .deploy-history
                                   -> при провале smoke и без миграций: авто-откат на прошлый sha
```

- Реестр: GHCR, пакеты публичные (репозиторий публичный, в образ web запекаются только публичные URL).
  Учётные данные на хосте не нужны.
- Образ web пока привязан к домену (`NEXT_PUBLIC_*` - аргументы сборки). CI собирает его с доменом
  из переменной репозитория `PROD_DOMAIN`. Это единственное Next-специфичное место инфраструктуры,
  в `compose.prod.yaml` помечено `# stage-2: заменить на runtime-конфиг`.
- `deploy.sh`: `flock`, отказ при отсутствии образа для sha, `up -d --wait` всего проекта
  (инфраструктурные сервисы обновляются тем же деплоем), чистка образов старше 5 релизов.
- `just rollback [sha]`: переключение `IMAGE_TAG` + `up -d --wait` + smoke.
- `smoke.sh` (общий для деплоя, CI и drill): `/api/v2/health/ready`, главная страница 200,
  анонимный `GET /content/<probe>`, presigned PUT+GET тестового объекта, запрос к Judge0 без токена = 401.
- Автоматический CD не вводим: хост за NAT, входящий SSH с раннеров под вопросом. Запуск деплоя
  остаётся ручным, но деплоится только то, что прошло CI.

### 5.8 Бэкап и восстановление

Остаётся `offen/docker-volume-backup`: pre-archive hook, шифрование, S3-цель, ротация и уведомления
у него штатные.

| Что      | Как                                                                                                                                                    |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Postgres | pre-hook в контейнере `db`: `pg_dump -Fc` для `ashyq` и `zitadel` + `pg_dumpall --globals-only` в том `db_dumps`; архивируется он, а не каталог данных |
| RustFS   | том целиком, на живую (ключи объектов неизменяемы). Потолок: при объёме > ~20 ГБ перейти на инкрементальный `rclone sync`                              |
| Redis    | `dump.rdb`                                                                                                                                             |
| Секреты  | `.env`, `server.env`, `pat.txt`                                                                                                                        |
| Judge0   | не бэкапится                                                                                                                                           |

- Метки `stop-during-backup` удаляются со всех сервисов.
- Цель: локально `./backups` (7 дней) + внешний S3-совместимый бакет (30 дней), архив шифруется
  парольной фразой, которую владелец хранит вне хоста.
- `restore.sh <архив>`: на пустом проекте поднимает `db`, восстанавливает дампы, раскладывает тома,
  запускает стек и smoke.
- `restore-drill.sh`: то же в проекте `ashyq-drill` на других портах, плюс сверка счётчиков
  (`users`, `courses`, число объектов в бакетах) с продом, замер времени, снос. Каталог для
  распаковки задаётся `RESTORE_DIR` вне репозитория; `temp-restore/` из рабочего дерева уезжает.
- Drill-стек - обязательный полигон для каждой рискованной прод-операции этапа (5.3, смена образа БД).

## 8. Приёмка этапа

1. Чистая машина: `git clone` -> `just dev-up` -> тесты сервера зелёные; Windows+podman и Linux+docker.
2. `stack-smoke` в CI зелёный, включая прогон с заглушкой вместо web.
3. Прод работает на образах из GHCR; на хосте нет сборочных кэшей и bun.
4. Ночной бэкап: без простоя, шифрованный, вне хоста; drill пройден дважды, RTO записан и <= 2 ч.
5. `docker compose exec web env` не содержит ни одного секрета; `redis-cli ping` без пароля и
   запрос к Judge0 без токена отклоняются; из контейнера Judge0 `db:5432` недостижим;
   `SELECT rolsuper FROM pg_roles WHERE rolname = current_user` из приложения возвращает `false`.
6. `git grep '_next\|NEXT_' -- compose*.yaml infra/` находит только помеченный блок сборочных аргументов web.
7. Закрыты F#1, F#2, F#3, F#8, F#9, F#10, F#11, F#13 (в части каркаса CI).
8. `git diff` по `apps/` - только файлы шва.
9. `main` зелёный, кроме гейтов веба из базовой линии.

## 11. Сознательно не делаем

- Kubernetes, Swarm, второй хост, балансировщик, zero-downtime деплой.
- Ansible/Terraform: настройка хоста - один раздел `RUNBOOK.md`.
- Prometheus/Grafana/Loki, sops/Vault, Renovate/Dependabot.
- Автоматический CD по push.
- Переименование суперпользователя `openu`, томов и каталога прод-деплоя: риск выше пользы.

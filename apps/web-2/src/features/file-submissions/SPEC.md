# file-submissions

Операции: getActivityFileSubmission, myAttempts, startDraft, saveFileSubmissionDraft, submit, fileUrl, updateFileSubmission, publishFileSubmission, unpublishFileSubmission

Сдача файла учащимся `/learn/$courseId/$activityId/submission` (фокус-режим, вход из карточки плеера) и настройка
задания в студии активности `/teach/courses/$courseId/activities/$activityId/{edit,settings}` (5.3, 5.4). Проверка
работ - срез 6.1 (`grading`). Каталог сообщений - `submission`.

## Поведение

- B-FSB-01 Страницу сдачи открывает только записанный на курс: остальные видят «Нет доступа» на том же адресе (как
  плеер), гость попадает на вход; активность не из курса или другого типа - «Активность не найдена».
- B-FSB-02 Задание без настройки или с неопубликованной настройкой (сервер отвечает учащемуся 404; 23 импортированных
  задания, Q-2026-09-26-1) - «Задание ещё не настроено» одной фразой, без загрузки и без ошибки.
- B-FSB-03 Шапка задания: название, срок с датой и временем в поясе платформы и метка «Срок прошёл» после него;
  правило опоздания (не принимаются / без штрафа / минус N % в день не больше M дней / после даты - 0 баллов);
  условие в markdown; требования: сколько файлов, до скольких МБ каждый, какие типы (или «любые»).
- B-FSB-04 Файл загружается через общее поле (`file-submission`) по правилам задания: тип и размер проверяются до
  загрузки, причина - под полем. Загруженный файл сразу прикрепляется к черновику (`PATCH .../draft` с `If-Match`
  открытой попытки; первый файл открывает черновик); «Убрать» открепляет. На пределе числа файлов поле выключено и
  сказано почему.
- B-FSB-05 «Сдать работу» (без файлов выключена) спрашивает подтверждение: номер попытки из предела и что файлы
  нельзя менять до проверки. Сдача идёт с `Idempotency-Key` (тот же при повторе без ответа) и `If-Match`; после -
  сообщение «Работа сдана».
- B-FSB-06 Квитанция: когда сдана, номер попытки, «С опозданием», файлы и «Ожидает проверки»; оценка выставлена, но
  не опубликована - «Оценка появится после публикации».
- B-FSB-07 Результат: оценка в процентах, при штрафе - оценка без штрафа и процент штрафа, отзыв (markdown) и баллы
  по критериям рубрики. «Новая попытка» есть, пока попытки не кончились и ничто не мешает; на пределе её нет.
- B-FSB-08 Возвращённая работа: «Работа возвращена на доработку» и отзыв; файлы той же попытки снова можно менять,
  «Сдать работу» сдаёт её повторно.
- B-FSB-09 Причины сервера (`disabled_reasons`: срок прошёл и опоздания не принимаются, нужно исправление, курс в
  архиве) заменяют загрузку и сдачу текстом причины. Отказ записи (403, 409) перечитывает задание, причина
  появляется на месте.
- B-FSB-10 Свои файлы скачиваются кнопкой с именем файла: она берёт короткую подписанную ссылку
  (`file-submission-files/{id}/url`): изображение и PDF открываются в новой вкладке, остальное скачивается (B-FSB-19).
- B-FSB-11 История - все попытки из `/me`, новые сначала: номер, статус, дата сдачи или «Черновик», оценка, если
  выпущена.
- B-FSB-12 Изменение черновика, который успел измениться в другой вкладке (412), открывает диалог конфликта;
  «Обновить и повторить» применяет то же действие к свежему черновику.
- B-FSB-13 Студия, `edit` задания: метка «Черновик» / «Опубликовано» / «В архиве»; черновик говорит, что учащиеся
  задание не видят; «Опубликовать задание» (без условия - ошибка сервера под кнопкой); после - сообщение, метка
  «Опубликовано» и переключатель «Опубликовано» в шапке включён.
- B-FSB-21 «Снять с публикации» (есть в `allowed_actions`: `unpublish`) спрашивает, затем задание - черновик, его
  активность скрыта (переключатель шапки выключен), сообщение. «Опубликовать задание» - тоже по `allowed_actions`.
- B-FSB-14 Условие - markdown-редактор со своим «Сохранить»; у опубликованного задания пустое условие сервер не
  принимает (ошибка на месте).
- B-FSB-15 Рубрика: критерии (название, максимум баллов) добавляются и убираются, своё «Сохранить»; уровни
  критериев, пришедшие из старых данных, сохраняются как были.
- B-FSB-16 Студия, `settings` задания: под названием - «Файлы» (сколько файлов, предел МБ, пусто - без предела;
  типы галочками по группам, ни одной - любые) со своим «Сохранить»; число вне диапазона сервера - ошибка под полем.
- B-FSB-17 «Сроки и попытки»: срок (дата и время в поясе платформы, пусто - без срока), «Принимать после срока»,
  правило опоздания (без штрафа / процент в день и предел дней / дата отсечки), предел попыток (пусто - без предела),
  выпуск оценок (сразу / вместе); своё «Сохранить».
- B-FSB-18 Страница сдачи и студия задания работают на kk и en: тексты из каталога, `<html lang>` верный.
- B-FSB-19 В новой вкладке (`disposition=inline`) открываются только изображение (не SVG) и PDF; любой другой файл
  (HTML, SVG, XML...) берётся с `attachment` и скачивается ссылкой `download` своего origin, в браузере не открывается.
- B-FSB-20 Каждое «Сохранить» студии задания (условие, рубрика, файлы, сроки) уходит с `If-Match: version`; 412 -
  диалог конфликта, «Обновить и повторить» перечитывает задание и отправляет то же.

## Изменено

- Сдача файла - свой адрес `/learn/$courseId/$activityId/submission`, а не часть страницы активности.
- Файл прикрепляется к черновику сразу после загрузки: отдельной кнопки «Сохранить черновик» нет.
- Подтверждение сдачи - всегда, а не только при пределе попыток.
- Поле загрузки кита берёт один файл за раз (выбор или перетаскивание); несколько файлов - по очереди.
- Студия: условие и рубрика - во вкладке `edit`, правила файлов, сроки и попытки - в `settings`; видимость
  активности - переключатель шапки, публикация задания - кнопка в `edit`.
- Опроса по таймеру нет: статус после проверки обновляется при возврате на вкладку и при открытии страницы.

## Не переносится

- Поверхность исправления («Пройти исправление») - срез AI 6.3; здесь только текст причины.
- Панель AI и «Предпросмотр» в студии задания; очередь и проверка работ - срез 6.1.
- Правка уровней критериев рубрики: нужна там, где проверяющий выбирает уровень (6.1).

## Ждёт сервера

- У `FileSubmission` нет `allowed_actions`, а у `Attempt` они только проверяющего (`save`, `publish`, `return`):
  начать, сдать, исправить выводятся из статуса попытки, `disabled_reasons` и `max_attempts` (B-FSB-07, B-FSB-08).
- Тело `POST /file-submissions/{id}/submit` в контракте - схема теста `SubmitRequest` (`answers`,
  `violation_count`): имя совпало со схемой сервера `{files?}`. Веб шлёт `{}`.
- Ответ `POST .../publish` не несёт новой `version` активности: веб поднимает её в кэше сам.
- Диапазоны полей (файлов 1-25, МБ 1-500, попыток 1-50, процент 0-100, дней от 1) и правило загрузки
  `file-submission` (100 МБ, любые типы) не объявлены в контракте: ошибки приходят 422 от сервера.

## Не перенесено (контракт есть)

- Отказ записи (403) несёт код (`attempt-past-due`, `remediation-required`) и `details.reasons`: веб не различает их и
  перечитывает задание.

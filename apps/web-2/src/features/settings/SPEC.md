# settings

Операции: myProfile, updateMyProfile, changePassword, listSessions, revokeSession, totpEnroll, totpVerify, totpRemove, dashboard, updatePreferences, publicProfile, userCourses

## Поведение

- B-SET-01 `/settings` открывает «Профиль»; разделы - вкладки-маршруты «Профиль», «Безопасность», «Оформление», «Уведомления»; гость уходит на вход.
- B-SET-02 Профиль: имя, организация и «О себе» заполнены из профиля, почта и имя пользователя видны только для чтения; «Сохранить» - «Сохранено», новое имя сразу в меню профиля; пустое имя или организация - ошибка сервера под полем, ввод не теряется. Со страницы есть ссылка на свой публичный профиль.
- B-SET-03 Фото профиля: файл не-изображение или больше 5 МБ отклоняется до загрузки, сообщение говорит, что сделать.
- B-SET-04 Выбранное фото загружается через `shared/api/upload.ts` (createUpload, PUT, finalizeUpload) с назначением `avatar` и сразу ставится в профиль (`avatar_upload_id`).
- B-SET-05 Конструктор публичного профиля: раздел любого из 8 типов добавляется в конец, переставляется вверх и вниз, удаляется; пустые даты и подписи не отправляются (поле опускается).
- B-SET-06 Ссылки, изображения и логотипы конструктора принимают только адрес `http(s)`; иначе ошибка до отправки.
- B-SET-07 Пароль: неверный текущий - ошибка под полем «Текущий пароль»; успех - форма очищается, сообщение говорит, что другие сеансы завершены, и они исчезают из списка. Учётная запись только с Google видит пояснение вместо формы (UX-188).
- B-SET-08 Сеансы: текущий первым с меткой «Это устройство»; у каждого устройство (браузер и система из user agent, BUG-058), IP и дата последней активности; «Завершить» есть у всех, кроме текущего, идёт через подтверждение и убирает сеанс из списка; уже завершённый (404) тоже исчезает.
- B-SET-09 2FA: «Включить» показывает QR-код, ключ для ручного ввода и ссылку `otpauth://`; верный код включает защиту, неверный - ошибка под полем кода (BUG-083). Учётной записи с Google сказано, что вход через Google код не спрашивает (UX-198).
- B-SET-10 Отключение 2FA - через подтверждение; после него снова доступно «Включить».
- B-SET-11 Оформление: тема из 63 с четырьмя цветами превью, режим (как в системе, светлый, тёмный) и язык; «Сохранить» применяет тему и режим без перезагрузки и пишет тему в профиль (BUG-362).
- B-SET-12 Смена языка сохраняет `locale` профиля (`ru` / `kk` / `en`, ответ - `language`) и переключает интерфейс.
- B-SET-16 Там же «Показывать XP, уровни и награды» и «Показывать серию учёбы на главной» (`display`, по умолчанию
  включены); сохраняются вместе с остальными.
- B-SET-13 Уведомления: «Сообщать о начисленном XP» и «Показывать меня в лидерборде» читаются из `settings` профиля (snake_case, по умолчанию включены); «Сохранить» записывает их, после перезагрузки значения те же.
- B-SET-14 Публичный профиль `/users/$username`: имя, @имя пользователя, фото, «О себе» и курсы, которые пользователь создал или ведёт, со ссылками; приходит в SSR-документе; неизвестный пользователь - «Пользователь не найден».
- B-SET-15 Страницы настроек и публичного профиля работают на kk и en: тексты из каталога, `<html lang>` верный.

## Изменено

- Вкладки «Общие» и «Геймификация» стали «Профиль» и «Уведомления»; тема и режим ушли из «Общих» в «Оформление», язык - из меню в «Оформление» (и остался в меню профиля).
- Тема выбирается сеткой с превью и сохраняется кнопкой, без поиска, «случайной темы» и автосохранения через 1 с.
- Фото не уменьшается в браузере до 512 px WebP: файл уходит как есть, лимит 5 МБ - политика сервера.
- Удаление фото (UX-163) - через подтверждение. Удаление раздела конструктора - без подтверждения: до «Сохранить» ничего не записано.
- Порядок разделов меняется кнопками «Выше» / «Ниже» вместо перетаскивания; все разделы редактируются в одном списке, без выбора слева.
- Пароль: поля «Повторите пароль» и проверки правил в браузере нет (как в `auth`): правила проверяет сервер, ответ - под полем.
- Сеансы: показываются все, без «первых 5» и «показать все».
- 2FA: появился QR-код (старый веб показывал только ключ и ссылку).
- Счётчик символов «О себе» и ограничения длины до отправки убраны: лимиты - сервер (S-01).

## Не переносится

- `OrganizationPrompt` (неснимаемый диалог на каждой странице `/dash`, если организация пустая): организация - обычное поле профиля; сервер требует её при сохранении профиля (5.6).
- `display.animatedEffects` и `display.compactMode`: анимаций-украшений и плотности по выбору пользователя в новом вебе нет (DESIGN 5, 9).
- Сводка XP и уровня на странице настроек геймификации - раздел `/achievements`.
- Перечитывание сеансов и 2FA при возврате фокуса (UX-082, UX-107): Query обновляет данные старше 30 с.
- Раздел конструктора `gamification` не предлагается при добавлении (как в старом вебе); сохранённый остаётся с полем названия.

## Ждёт сервера

- `PreferencesPatch` в контракте объявляет только camelCase (`xpGain`, `showOnLeaderboard`): запись идёт ими, хотя
  сервер принимает и snake_case.
- Раздел `gamification` на публичной странице (XP и серии другого пользователя): нет публичной операции.
- Ограничения разделов конструктора (длины, число разделов, даты) в схеме контракта нет; поля профиля их объявляют.

## Не перенесено (контракт есть)

- Форма конструктора проверяется схемой, собранной из вариантов (`vBuilderDocument`), а не `vProfileSections`.

# markdown

Операции:

Один рендер markdown для контента (описания курсов, условия задач и вопросов, отзывы, объявления) и для
ответов AI, и markdown-редактор на ядре Tiptap 3 (@tiptap/markdown: markdown на входе и на выходе). Рендер разбирает
текст тем же разбором, что и редактор (одна схема, одна настройка `marked`), и рисует документ так, как его рисует
Tiptap только для чтения, без движка редактора.
Публичный API (`index.ts`): ленивые `MarkdownView`, `MarkdownEditor`; `sanitize`, `safeUrl`, `safeImageUrl`,
`hasRawHtml`, `markdownPlainText`, `markdownSummary`; `loadHighlighter` (подсветка кода, и для блоков кода редактора);
`codeHighlighter` (классы цветов кода, общие с редактором кода).
Типографика - общий класс `ab-prose` (`src/styles/prose.css`), тот же, что у редактора блоков; своих стилей текста
у фичи нет.

## Поведение

- B-MD-01 Рендер: GFM (таблицы, списки задач, зачёркивание, автоссылки), формулы `$...$` и `$$...$$` через KaTeX
  (грузится, только если в тексте есть `$`), блоки кода с подсветкой грамматиками CodeMirror (цвета - токены темы,
  светлая и тёмная, как в редакторе кода) и подписью языка. Широкая таблица прокручивается внутри себя.
- B-MD-02 Ссылки только http(s), mailto, относительные и якоря; остальные без адреса. Внешние открываются в новой
  вкладке с `noopener noreferrer`, внутренние - в приложении.
- B-MD-03 Изображения только из хранилища платформы (`/content/...`); чужие показываются подписью
  «Изображение: alt».
- B-MD-04 Сырой HTML в markdown никогда не исполняется: теги отбрасываются (текст между строчными тегами остаётся,
  блок HTML и комментарии - нет), одинаково в рендере, в редакторе, в браузере и на сервере.
- B-MD-05 `sanitize()` (DOMPurify) - единственный путь HTML-строки в DOM: убирает script, обработчики, style;
  без DOM (SSR) возвращает пустую строку.
- B-MD-06 Простой текст и сводка: разметка снимается, экранированная пунктуация остаётся буквальной (UX-030),
  сводка режется по слову с «…».
- B-MD-07 Markdown-редактор: на входе и выходе markdown; после правки и сохранения рендер даёт тот же документ
  (корпус G-14, `gates/corpus.ts`: тексты прода проходят без потерь), включая формулы, таблицы, списки задач и код.
- B-MD-08 Блок кода копирует код кнопкой; подпись кнопки меняется на «Код скопирован».
- B-MD-09 Ответ AI, приходящий потоком, - вежливая live-область (`live`); каждый кусок разбирается заново с
  отложенным приоритетом, код подсвечивается по мере роста.
- B-MD-10 Пока рендер грузится, на его месте простой текст абзацев; если рендер не загрузился (связь пропала),
  простой текст остаётся, а не ошибка страницы.

## Изменено

- Режимы рендера старого веба (prompt, taskDescription, codeProblem...) сведены к одному виду: размер текста
  задаёт место, где рендер стоит.
- Изображения больше не скрываются флагом `allowImages`: показываются только из хранилища платформы.
- Копирование кода без тоста (тост только после мутации, DESIGN 9).
- Пункты списков - абзацы, как в редакторе: у плотного списка между пунктами небольшой отступ.

## Не переносится

- Якорные ссылки у заголовков рендера (были только в описании курса): вернутся с оглавлением курса.
- Пресеты редактора (наборы кнопок по месту), режим исходника, валидация длины и предупреждения о незакрытых
  `$`/```: правила поля задаёт форма-потребитель по схеме контракта.
- Мигающий курсор потока AI: ответ объявляет live-область (B-MD-09).
- Сноски GFM (`[^1]`): у `marked` их нет; ссылка на сноску и её определение остаются текстом.

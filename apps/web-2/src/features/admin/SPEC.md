# admin

Операции: listUsers, createUser, assignRole, unassignRole, setUserStatus, listRoles, createRole, updateRole, deleteRole, setRolePermissions, getPlatform, updatePlatform, getConfig, updateConfig, adminAward, search, listGroups, getGroup, createGroup, updateGroup, deleteGroup, listGroupMembersPage, addGroupMembers, removeGroupMembers, getRole, getAdminUser

## Поведение

- B-ADM-01 `/admin/users` - один список всех пользователей: имя и @имя пользователя, почта, роли, статус, дата регистрации; новые сначала, «Показать ещё» по `next_cursor`; на 390 px таблица становится карточками.
- B-ADM-02 Поиск по имени, имени пользователя и почте живёт в URL (`?q=`); пустой результат - «ничего не найдено» и «Сбросить фильтры».
- B-ADM-03 Пользователь открывается в боковой панели по ссылке с `?user=<id>` (`GET /users/by-id/{id}/admin`): ссылку можно передать, после перезагрузки панель открыта; закрытие убирает параметр. Неизвестный или неверный id - «Пользователь не найден».
- B-ADM-04 Роли пользователя снимаются и добавляются в панели только при `manage_roles`; добавить можно роль с действием `assign`, которой у пользователя нет; таблица сразу показывает новые роли.
- B-ADM-05 «Отключить» (при `disable`) - подтверждение с именем пользователя, затем статус «Отключён» и «Включить» (при `enable`) без подтверждения; отказ сервера (`self-disable`, `last-admin`) - текст в диалоге.
- B-ADM-06 «Добавить в группу» в панели: выбор из групп, где есть `manage_members`; после - сообщение, пользователь среди участников группы.
- B-ADM-07 «Новый пользователь» - диалог (имя, фамилия, имя пользователя, почта, пароль - необязателен, тогда вход только через Google); занятые имя пользователя или почта - ошибка под полем; после - сообщение и панель нового пользователя.
- B-ADM-08 `/admin/roles`: роли в порядке сервера с названием, slug, приоритетом, видом (системная или своя) и числом прав; название системной роли - из каталога по `display_name_key`, своей - `display_name`.
- B-ADM-09 Страница роли `/admin/roles/$roleSlug` (`GET /rbac/roles/{slug}`): описание и права, сгруппированные по ресурсу (строки сервера как есть); неизвестный slug - «Роль не найдена».
- B-ADM-10 «Новая роль» - диалог (slug, название, описание, приоритет); пустое название - ошибка под полем, занятый slug - ошибка под slug; после - страница роли.
- B-ADM-11 На странице своей роли: секция названия, описания и приоритета (при `update`) и секция прав - по одному на строку (при `set_permissions`), у каждой своё «Сохранить»; неверная строка права - ошибка сервера под полем. У системной роли этих секций нет.
- B-ADM-12 Удаление роли (при `delete`) - подтверждение с названием; после - сообщение и список без неё.
- B-ADM-13 `/admin/platform`: название, подпись, описание, «О платформе» и почта заполнены из `GET /platform`; «Сохранить» - «Сохранено», после перезагрузки новые значения; пустое название - ошибка под полем.
- B-ADM-14 Логотип и обложка загружаются через `shared/api/upload.ts` с назначениями `platform-logo` и `platform-thumbnail` и сохраняются как `logo_upload_id` / `thumbnail_upload_id`; текущие показаны превью.
- B-ADM-15 `/admin/gamification`: дневной лимит XP и награда за каждый источник XP; пустое поле - значение платформы; «Сохранить» заменяет переопределения целиком (`PUT`), после перезагрузки значения те же; переопределения, которых нет на форме, сохраняются.
- B-ADM-16 «Начислить XP» - секция панели пользователя при `admin.gamification` (количество, причина); `idempotency_key` - поле тела, один на действие, пока сервер не ответил; после - сообщение с новым итогом XP пользователя.
- B-ADM-17 `/teach/groups`: группы (название, описание, число участников), новые сначала, «Показать ещё»; «Новая группа» - диалог (название, описание), после - страница группы.
- B-ADM-18 Страница группы `/teach/groups/$groupId`: участники со ссылками на профиль; секция названия и описания (при `update`) со своим «Сохранить»; неизвестная группа - «Группа не найдена».
- B-ADM-19 Участники добавляются поиском по людям (при `manage_members`) и убираются кнопкой у участника; без `manage_members` кнопок нет.
- B-ADM-20 Удаление группы (при `delete`) - подтверждение с названием; после - сообщение и список без неё.
- B-ADM-21 Страницы пользователей, ролей, платформы, геймификации и групп работают на kk и en: тексты из каталога, `<html lang>` верный.
- B-ADM-22 Участники группы - страницами по 20 с «Показать ещё» (`next_cursor`); число участников в шапке - `member_count` всей группы, добавленные встают в конец загруженного списка, удалённые уходят из него без повторного запроса страниц.
- B-ADM-23 Секции своей роли, платформы и группы сохраняют с `If-Match: <version>` - версией, с которой открыта страница; её двигают только ответы сохранений с этой же страницы (две секции роли или платформы друг другу не мешают), перечитывание - нет. Если объект за это время сохранили в другом месте - 412 и диалог конфликта, введённое остаётся; «Отмена» возвращает к форме, «Обновить и повторить» сохраняет введённое поверх новой версии.
- B-ADM-24 Удаление роли и группы уходит с `If-Match: version`; правила XP (`PUT /gamification/config`) - тоже: 412 -
  диалог конфликта, «Обновить и повторить» читает версию заново и отправляет введённое.
- B-ADM-25 «Создать» у пользователей, ролей и групп - по своим возможностям (`admin.users.create`, `admin.roles.create`,
  `groups.create`), отдельно от чтения: без права создавать кнопки нет.

## Изменено

- Два списка пользователей (`/dash/users/settings/users` и список в «Группах») стали одним `/admin/users`; роли, статус и группы - действия в боковой панели пользователя, а не модальные окна строки.
- Группы переехали из администрирования в пространство преподавания (`/teach/groups`); создание - диалог, правка и участники - страница группы, а не модальные окна.
- Роли: правка и права - страница роли, права своей роли редактируются списком строк.
- Настройки геймификации (N-5) и начисление XP администратором - новые экраны: в старом вебе их не было.

## Не переносится

- Привязка групп к курсам (`addGroupCourses`, `removeGroupCourses`, `groupsForCourse`) - вкладка `learners` рабочего места курса (срез `course-studio`).
- `listGroupCourses` (удалить с сервера): страница группы курсы не показывает, привязка читается со стороны курса (`groupsForCourse`).
- `listGroupMembers` (голый массив, удалить с сервера): заменён `listGroupMembersPage`.

## Ждёт сервера

- Группы пользователя (`GET /users/{user_id}/groups`): панель только добавляет в группу, состав групп виден на их страницах.
- Награды по умолчанию для источников XP не в контракте (дневной лимит 500 - только в описании `daily_xp_limit`): пустое поле подписано «по умолчанию» без числа.
- `sort` у `GET /users` - `unknown` в схеме (описание: `newest` | `name`), а не enum.
- Живое обновление списков при чужих изменениях: в `UserStreamEvent` нет событий пользователей, ролей и групп.

## Не перенесено (контракт есть)

- Сортировка и фильтры списка пользователей: `GET /users` принимает `sort`, `status`, `role`.
- `Idempotency-Key` у `createUser`, `createRole`, `createGroup`.
- `Platform.allowed_actions` (`update`) на `/admin/platform`.

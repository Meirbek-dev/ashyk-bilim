# auth

Операции: login, logout, register, verifyEmail, resendVerification, requestPasswordReset, confirmPasswordReset, googleStart

## Поведение

- B-AUTH-01 Вход по имени пользователя или почте и паролю; после успеха открывается путь из `redirect`, без него - `/home`; у каждого поля пароля (вход, регистрация, сброс, настройки) - кнопка «Показать пароль».
- B-AUTH-02 `redirect` принимает только внутренний путь этого сайта; чужой домен, `//host`, `\`, `javascript:` и пустое значение ведут на `/home`.
- B-AUTH-03 Неверный пароль, отключённая учётная запись и лимит попыток показываются на месте; при лимите сказано, через сколько минут повторить (`Retry-After`). Введённое имя сохраняется.
- B-AUTH-04 Если у учётной записи включена 2FA, сервер отвечает `mfa-required`: появляется поле кода (без кнопки Google), тот же вход отправляется с кодом. Неверный код - ошибка на месте; «Назад ко входу» возвращает к паролю и сохраняет имя.
- B-AUTH-05 Кнопка "Войти через Google" - ссылка на `/api/v2/auth/google?callback=<проверенный redirect>`; ошибка возврата (`/login?error=<код>`) показывается на шаге пароля и пропадает на шаге кода.
- B-AUTH-06 Регистрация: имя, фамилия, организация, имя пользователя, почта, пароль. Схема тела - из контракта, адрес почты (пустой, без @) проверяется вместе с остальными полями до отправки; ошибки полей сервера стоят под полями, `username-taken` и `email-taken` - под своими полями, значения не теряются. Запрос несёт язык интерфейса (`Accept-Language`, язык ссылки в письме) и `Idempotency-Key`.
- B-AUTH-07 После регистрации новая учётная запись сразу входит и открывается путь из `redirect` (ссылки «Регистрация» и «Войти» передают его друг другу), без него - `/home`; неподтверждённую почту подтверждают из баннера (B-AUTH-15). Без доставки почты (`email_verified` уже true) баннера нет. Если вход не удался - подтверждение почты с подставленным адресом или страница входа.
- B-AUTH-08 Подтверждение почты: адрес и код (из полей или из ссылки `?email=&code=`); неверный или устаревший код - ошибка под полем кода, адрес и код остаются; успех - сообщение и переход ко входу. Ссылку из письма открывает и вошедший с неподтверждённым адресом (регистрация сразу входит): страница не уводит его на главную, после подтверждения сеанс перечитывается (баннер уходит) и он попадает на главную.
- B-AUTH-09 Выход из меню профиля закрывает сессию и ведёт на главную; закрытые страницы после этого ведут на вход.
- B-AUTH-10 Вошедший на `/login`, `/signup`, `/verify-email`, `/reset-password` попадает на `/home` (кроме ссылок из писем с кодом: подтверждение своей неподтверждённой почты, B-AUTH-08, и сброс пароля - форма с кодом открывается); гость на закрытой странице - на `/login?redirect=<эта страница>` и после входа возвращается на неё.
- B-AUTH-11 Страницы входа, регистрации, подтверждения и восстановления пароля работают на kk и en: тексты из каталога, `<html lang>` верный.
- B-AUTH-12 Под паролем на `/login` - ссылка "Забыли пароль?" на `/reset-password`. Первый шаг: имя пользователя или почта; ответ всегда один - «Если такая учётная запись есть, мы отправили код на её почту.» и шаг кода (API отвечает 202 на любое имя: перебор учётных записей невозможен). Запрос несёт язык интерфейса (язык письма); лимит попыток - «Слишком много попыток. Повторите через N мин.» (`Retry-After`).
- B-AUTH-13 Шаг кода: код из письма и новый пароль (длины - из схемы контракта, ошибка видна до отправки). Неверный, использованный или устаревший код (`reset-code-invalid`) - ошибка под полем кода, ввод сохраняется; отказ политики пароля - под полем пароля. Успех - сообщение и переход ко входу с уже введённым именем (в состоянии истории, не в URL); сервер закрывает все сессии учётной записи, войти можно новым паролем. Имя хранится в памяти страницы, не в URL; ссылка из письма (`?email=&code=`) сразу открывает шаг кода с заполненным кодом. "Запросить код ещё раз" возвращает к первому шагу.
- B-AUTH-14 На `/verify-email` кнопка "Отправить код ещё раз" отправляет код на адрес из поля; ответ всегда один («Если адрес ждёт подтверждения, мы отправили новый код.»); при лимите - то же «Повторите через N мин.» (`Retry-After`). Пустой или неверный адрес - ошибка под полем почты, не общее сообщение формы.
- B-AUTH-15 Пока адрес не подтверждён (`email_verified` сессии), над содержимым - «Подтвердите почту»: код из письма подтверждает адрес на месте (баннер исчезает), «Отправить код ещё раз» шлёт новый, «Скрыть» убирает баннер до конца сессии браузера. Вход от подтверждения не зависит. Без доставки почты сервер считает адрес подтверждённым, баннера нет.
- B-AUTH-16 Сеанс вошедшей вкладки закончился (истёк, вышли в другой вкладке): страница входа, куда её отправил guard, над формой говорит «Сеанс истёк. Войдите снова, чтобы продолжить с того же места.»; после обычного «Выйти» и для гостя - нет; новый вход снимает отметку. Пока на странице есть несохранённые правки формы (или идёт загрузка файла), страница остаётся: сверху «Сеанс истёк. Войдите снова в новой вкладке — введённые данные и загружаемые файлы здесь не пропадут.» со ссылкой входа в новой вкладке; после входа там «Сохранить» здесь работает.
- B-AUTH-17 Гость пришёл на вход или регистрацию с публичной страницы (курс, подборка, профиль, сертификат, поиск; и через «Войти» / «Регистрация» в шапке, кроме главной): «Назад» ведёт туда (без `enroll`), иначе на главную; после входа он возвращается туда же. После «Записаться» над формой: «Войдите, и мы сразу запишем вас на курс.» / «Создайте учётную запись, и мы сразу запишем вас на курс.». На регистрации тоже есть «Зарегистрироваться через Google» (Google создаёт учётную запись при первом входе).

## Изменено

- Адреса: `/login`, `/signup`, `/verify-email` вместо `/{locale}/auth/...`; параметр возврата - `redirect`, не `returnTo`.
- После регистрации учётная запись сразу входит (старый веб вёл на вход, первая версия нового - на подтверждение почты).
- Выход ведёт на главную, а не на страницу входа.
- Поля «Повторите пароль» нет; правила пароля - подсказкой под полем. Локально проверяется только длина из схемы
  контракта (регистр, латиница: UX-201 - нет): остальные правила проверяет сервер, ответ - под полем.

## Не переносится

- Рассылка выхода в другие вкладки и сброс темы при выходе (BUG-380): сессия обновляется при фокусе вкладки, тема - срез `settings`.
- Автофокус поля кода 2FA: кит не даёт `autoFocus`, порядок табуляции ведёт к полю.

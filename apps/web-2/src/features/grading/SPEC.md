# grading

Операции: getActivity, getActivityAssessment, getActivityFileSubmission, assessmentReviewQueue, fileSubmissionReviewQueue, stats, fileSubmissionReviewStats, itemAnalytics, exportAssessmentSubmissionsCsv, exportFileSubmissionCsv, publishGrades, publishFileGrades, returnGrades, returnFileGrades, extendDeadline, extendFileDeadline, getBulkAction, reviewSubmission, saveGrade, gradingHistory, fileGradingHistory, getAttempt, gradeAttempt, fileUrl, gradebook, exportGradebookCsv, groupsForCourse

Одно место проверки (5.4 «Проверка»): очередь работ активности `.../activities/$activityId/submissions`, проверка одной
работы `.../submissions/$submissionId` (фокус-режим), сводка `.../results` и журнал оценок курса
`/teach/courses/$courseId/gradebook`. Тест, экзамен и задача с кодом проверяются по сдачам оценивания, отправка файла -
по попыткам; `$submissionId` - id сдачи или id попытки, по типу активности (входящие ведут сюда же). Каталог - `grading`.

## Поведение

- B-GRD-01 Очередь: одна таблица для обоих видов работ - учащийся (имя и логин), попытка, когда сдана, «С опозданием»,
  статус, оценка (прочерк, пока оценки нет) и действие строки в проверку. У активности без сдач (страница, видео,
  документ) - одна фраза.
- B-GRD-02 Фильтры в URL: статус ссылками (`?status=needs_grading|graded|published|returned`), поиск учащегося
  (`?q=`, Enter), «Только с опозданием» (`?late=true`); неизвестное значение - вся очередь; пустой
  результат с фильтром - «ничего не найдено» и «Сбросить фильтры».
- B-GRD-03 Сортировка заголовками столбцов (когда сдана, оценка, попытка) живёт в URL (`?sort=&order=`) и уходит на
  сервер (у оценивания и у отправки файла).
- B-GRD-04 «Показать ещё» запрашивает следующую страницу по `next_cursor`; без курсора кнопки нет.
- B-GRD-05 Числа - с сервера: в заголовке - всего сдач, на ссылках статусов - число по статусу (`stats`,
  `fileSubmissionReviewStats`).
- B-GRD-06 «Скачать CSV» - ссылка на выгрузку сервера с языком интерфейса (`?lang=`).
- B-GRD-07 «Опубликовать оценки» (право `grade` оценивания) спрашивает подтверждение с числом проверенных
  неопубликованных работ; после - сообщение с числом опубликованных и тех, что ещё ждут проверки.
- B-GRD-08 Выбранные строки «Вернуть на доработку»: только строки, где сервер разрешает `return`, одним запросом
  (`returnGrades` / `returnFileGrades`); сервер возвращает каждую по её текущей версии и считает пропущенные
  (опубликованные, изменённые за это время) - их число показано, остальные возвращаются.
- B-GRD-09 Выбранным «Продлить срок»: дата и время в поясе платформы и причина; учащиеся не из курса и
  сотрудники курса не продлеваются, их имена названы; прошедшая дата - ошибка под полем.
- B-GRD-10 Проверка работы - фокус-режим: учащийся, попытка, дата сдачи, «С опозданием» и штраф, статус; «Назад» - в
  очередь с теми же фильтрами; «Предыдущая» / «Следующая» - соседние работы загруженной очереди с этими фильтрами.
- B-GRD-11 Ответы по заданиям: формулировка, ответ учащегося по виду (выбор, текст, форма, соответствие, код только
  для чтения), правильный ответ и вердикт автопроверки на языке интерфейса.
- B-GRD-12 Баллы по заданию - в шкале задания (0..максимум), подставлены до сотых; вне диапазона - ошибка под полем;
  рядом итог по заданиям в процентах; отправляются только изменённые задания.
- B-GRD-13 Итоговая оценка 0..100 - необязательное переопределение (пусто - по заданиям; очищенное сохранённое
  переопределение уходит как `null`), общий отзыв учащемуся.
- B-GRD-14 Кнопки «Сохранить черновик», «Опубликовать», «Вернуть на доработку» - только из `allowed_actions`; запись
  с `If-Match`; ответ сервера заменяет работу в кэше и строку очереди; сообщение в прошедшем времени.
- B-GRD-15 Сохранение поверх чужой проверки (412) открывает диалог конфликта и не теряет ввод; «Обновить и повторить»
  берёт свежую версию и отправляет то же действие. Иной отказ (409: есть задания без баллов) - текст на месте.
- B-GRD-16 Попытка с файлами: файлы скачиваются по короткой подписанной ссылке своего origin (`path`) в новой
  вкладке, изображение и PDF открываются здесь же (`disposition=inline`); критерии рубрики с баллами 0..максимум, итог 0..100 (нужен для сохранения и публикации),
  отзыв.
- B-GRD-17 История оценивания (оценивание) - свёрнутый раздел: когда, оценка, штраф, черновик или опубликована, отзыв.
- B-GRD-18 Сводка `results` оценивания: всего, ждут проверки, проверено, опубликовано, возвращено, с опозданием,
  средняя оценка, доля сдавших, распределение по диапазонам, статистика по заданиям; у отправки файла - фраза, что
  сводки нет.
- B-GRD-19 Журнал оценок: учащиеся × оцениваемые активности курса, в ячейке статус и оценка; ячейка ведёт в проверку
  ждущей попытки, если она есть, иначе оценки, что засчитана; «Показать ещё»; «Скачать CSV» с языком.
- B-GRD-20 Фильтры журнала в URL: поиск учащегося (`?q=`) и «Есть работы на проверку» (`?pending=true`); уходят на
  сервер (`q`, `status=needs_grading`), страницы приходят уже отфильтрованными.
- B-GRD-21 На узком экране журнал - карточки учащихся со строкой на активность.
- B-GRD-22 Округление: сумма баллов округляется один раз до сотых (99,99 не становится 100), подставленный балл - до
  сотых, балл переводится в шкалу задания и обратно.
- B-GRD-23 Очередь, проверка, сводка и журнал работают на kk и en: тексты из каталога, `<html lang>` верный.
- B-GRD-24 Фильтр «Группа» (`?group=`, группы курса из `groupsForCourse`) в обеих очередях, в счётчиках очереди файлов
  и в журнале уходит на сервер (`group_id`); проверка идёт по очереди с той же группой. У курса без групп (или если
  проверяющему нельзя читать группы, 403) фильтра нет.
- B-GRD-25 Очередь отправки файла: счётчики из `fileSubmissionReviewStats` (с группой), «Опубликовать оценки»
  (`publishFileGrades`: сообщение с числом опубликованных и пропущенных) и «Продлить срок» (`extendFileDeadline`,
  выполняется сразу) - те же правила выбора учащихся, что у оценивания.
- B-GRD-26 История оценивания попытки с файлами (`fileGradingHistory`) - тот же свёрнутый раздел: когда, оценка, штраф,
  статус записи, отзыв.
- B-GRD-27 Продление срока оценивания - массовое действие воркера (202): веб спрашивает `getBulkAction` раз в секунду
  (до 20 раз) и только потом показывает «Срок продлён учащимся: N» и перечитывает очередь; `failed` - ошибка в
  диалоге; не завершилось - «поставлено в очередь».

## Изменено

- Три места проверки (очередь студии, рабочее место файла, журнал) стали одним: очередь -> работа; журнал и входящие
  ведут в ту же проверку.
- Пагинация номерами в журнале и очереди заменена на «Показать ещё» (keyset); «нижняя граница» итогов исчезла -
  число берётся из `stats`.
- Баллы задания вводятся в шкале задания, а не в долях 100 (перевод - `toItemScale`).
- Живой поток курса (`/courses/{id}/grading/events`) и опрос при его потере не переносятся: изменения своих действий
  попадают в кэш сразу, чужие - при возврате на вкладку.

## Не переносится

- Аннотации текста ответа и выбор уровня рубрики: в контракте нет ни хранения аннотаций, ни уровня в `RubricScore`.
- «Заметка для аудита» (`audit_note`): журнал аудита в студии оценивания - срез `assessments`.
- Массовые «Пересчитать» и «Выставить оценку»: у `BulkActionType` они есть, операций нет.
- Анализ AI (срез 6.3): `ReviewPage` даёт слот `aside`; без него панели нет.

## Ждёт сервера

- `stats` оценивания не принимает `group_id`: с фильтром по группе числа на ссылках статусов остаются по всему курсу
  (у отправки файла - по группе).
- `GradebookCell` без `allowed_actions` проверяющего: ячейка журнала ведёт в проверку, права проверяются там.

# notifications

Операции: listNotifications, unreadCount, markNotificationRead, markAllNotificationsRead, getNotificationPreferences, putNotificationPreferences

Поток `myEvents` (`GET /me/events`) читает `shared/api/events.ts`; таблица "событие -> ключи" - `shared/api/event-invalidations.ts`.

## Поведение

- B-NOT-01 Колокольчик в верхней панели только у вошедшего: число непрочитанных из `unreadCount`, без непрочитанных - без числа, больше 99 - "99+"; подпись кнопки называет число.
- B-NOT-02 Колокольчик открывает панель: 5 последних уведомлений, "Прочитать все" (только когда есть непрочитанные) и ссылка "Все уведомления" на `/notifications`; без уведомлений - "Уведомлений пока нет".
- B-NOT-03 `/notifications`: новые сверху, "Показать ещё" по `next_cursor`; фильтр "Только непрочитанные" живёт в URL (`?unread=true`) и переживает перезагрузку; пусто - своё сообщение для каждого фильтра.
- B-NOT-04 Уведомление: значок и подпись типа, текст с названиями из payload (курс, задание, автор, заявитель, срок), дата; непрочитанное отмечено меткой "Новое".
- B-NOT-05 Уведомление ведёт к цели, собранной из id payload: оценка и возврат - активность в плеере (работа с файлами - страница сдачи), срок - активность, объявление - `/courses/$courseId/updates`, ответ в обсуждении - обсуждения курса с открытой веткой, заявка соавтора - `/teach/courses/$courseId/team`. Переход по непрочитанному отмечает его прочитанным.
- B-NOT-06 "Отметить прочитанным" у непрочитанного и "Прочитать все" в заголовке: счётчик берётся из ответа сервера, список меняется в кэше, без повторных запросов.
- B-NOT-07 Новое уведомление приходит потоком (`notification.created`): открытая страница показывает его первым и увеличивает счётчик без перезагрузки и без запроса списка.
- B-NOT-08 Отметка прочитанного в другой вкладке (`notification.read`) ставит счётчик из события и отмечает одно или все уведомления в списке.
- B-NOT-09 `/settings/notifications`: переключатель на каждый из 7 типов, значения из `getNotificationPreferences`; "Сохранить" отправляет весь набор, после перезагрузки значения те же.
- B-NOT-10 Начисление XP (`xp.awarded`) показывает обычный тост "+N XP", если в настройках не выключено "Сообщать о начисленном XP"; данные достижений и лидерборд обновляются.
- B-NOT-11 Поток: одно соединение на вкладку, только у вошедшего, открывается после гидрации; обрыв - переподключение с нарастающей задержкой (до 30 с), а соединение, прожившее дольше 30 с, переподключается сразу; возобновление отправляет `Last-Event-ID`; без известного id после переподключения перезапрашиваются активные данные; скрытая вкладка закрывает поток, возврат открывает его снова; 401 и `closed` закрывают поток и сессию.
- B-NOT-12 Таблица "событие -> ключи" покрывает каждое событие контракта (проверка типов): `grading.updated` - очереди проверки, работа, журнал оценок, сдача и её история; `submission.updated` - состояние учащегося, лента, "Сегодня", работа, задание и свои сдачи; `xp.awarded` - достижения; события уведомлений кэш меняют сами (B-NOT-07, B-NOT-08).
- B-NOT-13 Страница уведомлений и колокольчик работают на kk и en: тексты из каталога, `<html lang>` верный.
- B-NOT-14 Событие не перезапрашивает чтение, пришедшее после него: время события - id записи потока (мс), если он согласован с `sent_at`, иначе конец секунды `sent_at`; время чтения (`dataUpdatedAt`) переводится в часы сервера смещением из заголовков `Date` ответов API (оценка снизу, без неё - перезапрос). Изменение коллеги после чтения перезапрашивает его; эхо своей записи, пришедшее позже её перезапроса, - нет.

## Изменено

- Уведомлений в старом вебе не было (U-12): об оценке студент узнавал, только открыв задание; XP показывался отдельным конвейером тостов, теперь - событие потока и обычный тост (5.6).
- Два потока SSE (курс, сдача) и опрос заменены одним потоком пользователя (7.7).

## Не переносится

- Email и push (16: сознательно не делаем).

## Ждёт сервера

- Продление срока одному учащемуся (индивидуальное исключение) не создаёт уведомление `deadline_extended`: его создаёт только массовое продление (L-4).
- События `deadline.extended` в потоке нет: открытые страницы сроков обновляются только по фокусу вкладки.
- Администратор платформы не получает `grading.updated` (только автор и соавторы курса).

# ai

Операции: scopeCapabilities, qaChat, qaThreads, qaThread, deleteQaThread, studyAskQueue, streamRun, runArtifacts, cancelRun, queueCourseAnalysis, latestCourseAnalysis, reviewCourseFinding, publishCourseAnalysis, queueSubmissionAnalysis, latestSubmissionAnalysis, queueRemediation, latestRemediation, studentRemediation, completeRemediation, queueLectureReview, lectureReviews, dismissLectureSuggestion, adminSettings, setFeatureSwitch, usage, adminRuns, adminRunDetail, adminEvals

Одна панель AI (`AiPanel`) в правом слоте плеера (`student-activity`) и студии активности (`teacher-studio`) и в
листе страницы курса (`course-page`). Вкладки панели - из `GET /ai/capabilities/scope/{course_id}`. Вкладка и тред
живут в URL (`?ai=`, `?aiThread=`). Потоки - POST + AG-UI через `@ag-ui/client` поверх fetch SDK (`transport.ts`),
без опросов и таймеров. Анализ курса - на вкладке `overview` рабочего места курса; анализ сдачи и барьер -
экспорт `SubmissionAiPanel` для среза 6.1; `/admin/ai` - настройки, расход, запуски, оценки.

## Поведение

- B-AI-01 Панель есть у вошедшего: в плеере и студии - правая панель (на узком экране - лист), на странице курса -
  кнопка «Спросить ИИ», открывающая лист; гость не видит кнопку, запроса возможностей нет (BUG-159).
- B-AI-02 Недоступный ИИ (`available: false`) - одна строка причины (ИИ отключён, на этой активности ИИ закрыт,
  нет включённых режимов) без поля ввода. В плеере колонки ИИ и её кнопки на телефоне тогда нет вовсе.
- B-AI-03 Вкладки - из `modes`: «Вопросы» (`ask`), «Учёба» (`explain`/`practice`, только учащийся), «Критика материала»
  (студия, функция `lecture_authoring_enabled`), «Работа над ошибками» (плеер, есть сессии этой активности);
  `?ai=` выбирает вкладку, неизвестная - первая доступная.
- B-AI-04 Учёба: режим (объяснить, практика, карточки, конспект, углубить; под кнопками - строка, что даст режим),
  вопрос, «Спросить» -> очередь -> поток с шагом сервера и «Остановить» -> ответ markdown-рендером, вопросы практики
  с раскрываемым ответом, карточки, ссылки на источники и предложения продолжить (нажатие - новый вопрос).
- B-AI-05 Отправка выключена при пустом вопросе и пока запуск идёт.
- B-AI-06 Запуск: очередь -> поток -> готово / ошибка / отменён; оборванный поток сразу переподключается с
  `Last-Event-ID` последнего id потока (до 3 раз подряд без продвижения), отказ API (404, 429) окончателен; поздние
  события завершённого запуска ничего не меняют; уход со страницы обрывает поток.
- B-AI-07 «Остановить» отправляет отмену запуска; итог - «Запуск ИИ отменён».
- B-AI-08 Ошибки по коду: исчерпан бюджет (`ai-budget-exhausted`), ИИ отключён, часовой лимит - текст кода и
  «Повторить»; отказ очереди показывается в панели, а не падением страницы (UX-093).
- B-AI-09 Вопросы: ответ приходит потоком и рисуется markdown-рендером с объявлением для экранного чтеца; источники
  - список под ответом; первый вопрос создаёт тред, его id попадает в `?aiThread=`.
- B-AI-10 Вопрос и частичный ответ остаются на экране, пока сохранённый тред не содержит этот `client_turn_id`
  (UX-299); у ответа, оборванного «Остановить» или ошибкой, - отметка «Ответ не завершён».
- B-AI-11 Ошибка хода - текст кода и «Повторить»: повтор уходит с тем же `client_turn_id`, сервер отдаёт сохранённый
  ответ.
- B-AI-12 Треды: название или начало последнего сообщения, число сообщений, дата; выбор - `?aiThread=`; «Новый
  тред»; удаление - подтверждение с названием, удалённый открытый тред снимает выбор.
- B-AI-13 Анализ курса (`overview`, преподаватель): пусто - «Анализировать»; запуск с шагами и «Остановить»; отчёт:
  оценка и прошлая оценка, статус (черновик, нужна проверка, опубликован), «Содержимое изменилось» при `stale`,
  резюме, сильные стороны, риски, рекомендации с приоритетом; «Перезапустить».
- B-AI-14 Рекомендация: «Принять», «Отклонить», «Запланировать» (`task_created`: только отметка, задача нигде не
  создаётся) -> отметка сервера и сообщение; ответ кладётся в кэш.
- B-AI-15 «Опубликовать» анализ - подтверждение, затем статус «Опубликован» и сообщение.
- B-AI-16 Анализ сдачи (`SubmissionAiPanel`): пусто - «Анализировать»; запуск; итог: резюме, пробелы с важностью и
  доказательством, следующий шаг.
- B-AI-17 Барьер: «Назначить работу над ошибками» - подтверждение, затем очередь с `gate_mode`; выключено без
  анализа и пока барьер действует (назначен, в работе, не пройден); пройденный - «Работа над ошибками пройдена».
- B-AI-18 Критика материала (студия, любая активность: лекция, видео, документ, код): список активных разборов; «Проверить материал» -> запуск -> новый разбор;
  предложение: приоритет, место, обоснование, замена markdown-рендером; «Скрыть» убирает его (`dismiss`).
- B-AI-19 Работа над ошибками (учащийся, плеер): мини-лекция, цели, вопросы с полем ответа (выбор, если у вопроса
  есть варианты, иначе строка); «Завершить» доступно, когда ответ есть у каждого вопроса, и отправляет `answers`:
  балл считает сервер, проходной - `pass_threshold` (70 по умолчанию); итог - «Пройдено» или «Не пройдено».
- B-AI-26 Там, где барьер держит учащегося (`REMEDIATION_REQUIRED`: вход теста и экзамена, задание с файлом, задача с
  кодом), под причиной - сессии этой активности (как B-AI-19, `RemediationGate`); прохождение перечитывает состояние
  попытки страницы, и барьер снимается без перезагрузки, как в старом вебе; блок разбора уходит со страницы, и
  уведомление говорит «Разбор ошибок пройден: можно начать новую попытку».
- B-AI-27 Источник ответа - активность этого курса (`source_type: activity`, id из `source_uuid` или `activity:<id>`) - ссылка в плеер на неё, как в старом вебе; прочие источники - текстом.
- B-AI-28 Рекомендация с отметкой (`finding_reviews[finding-N]`) показывает её («Принято», «Отклонено», «Запланировано») и дату вместо кнопок.
- B-AI-29 Под анализом работы в проверке - «Добавить в отзыв»: обращённые к учащемуся «Что стоит повторить:» (пробелы с целью) и «Следующий шаг: …» дописываются в общий отзыв формы оценки (под написанным, ничего не стирая); резюме и свидетельства - для учителя, их в черновике нет; нечего предложить - кнопки нет.
- B-AI-30 Проверяющий видит назначенный урок разбора: свёрнутый блок с названием (и результатом учащегося, когда он есть), целями и текстом урока.
- B-AI-31 Цитата источника, которую модель взяла в машинном виде (JSON настроек, `"prompt":"..."`), не показывается: остаётся название источника.
- B-AI-20 `/admin/ai`: ИИ включён, провайдер готов, режим черновика, модель, лимиты токенов; функции с источником
  (переключатель или окружение); расход: запуски, токены, остаток бюджета и доля израсходованного.
- B-AI-21 Запуски: фильтры в URL (дни 1/7/30, статус, вид, провайдер или модель - подстрока, курс - из строки запуска «Только этот курс»), «Показать ещё» по `next_cursor`; застрявший запуск
  помечен; у неудачного под статусом - причина словами (код - в панели запуска); курс назван (`course_name`), под ним
  «Только этот курс».
- B-AI-22 Запуск (`?run=`): курс, модель, токены, длительность, код ошибки, журнал событий по порядку, артефакты и источники.
- B-AI-23 Оценки: «Запуски за всё время» по статусам, всего оценок, пройдено, средний балл, последние оценки; оценок
  нет - вместо нулей строка о том, откуда они берутся (команда `ashyq admin ai-eval`).
- B-AI-25 Переключатель функции - у кого есть `admin.platform` и где окружение разрешает (`editable`); иначе - «да/нет»
  (и строка «выключено в окружении»). Переключение -> ответ заменяет настройки в кэше, сообщение; отказ - текст под строкой.
- B-AI-24 Панель и `/admin/ai` работают на kk и en: тексты из каталога.

## Изменено

- Панель - одна для всех мест; режим и тред в search-параметрах роутера (было `history.replaceState`).
- Опрос `GET /ai/runs/{id}` каждые 2 с, переподключение через 2 с и `sessionStorage` с id запуска убраны: поток
  переподключается сразу, итог берётся из события; уход со страницы обрывает поток (запуск идёт дальше, итог - в
  `latest`).
- Опрос сессий работы над ошибками каждые 15 с убран: данные перечитываются после записи и при фокусе окна (Query).
- Критика материала - новый интерфейс (N-5).

## Не переносится

- Командные подсказки чата (карта курса, источники) и пять стартовых вопросов; шкала уверенности.
- Сводные метрики консоли (доля успешных, p50/p95, стоимость): поля есть у каждого запуска (`duration_ms`,
  `cost_estimate`), запуск показывает их в своей карточке, сводки нет; кнопки отмены запуска в админке.
- Флажок «я проверил доказательства» перед публикацией анализа.

## Ждёт сервера

- `FeatureCapability.key` - строка, а не enum; `StudyCompanionAnswer.flashcards` -
  `JsonValue[]`; `TOOL_CALL_RESULT.content` - JSON внутри строки.

## Не перенесено (контракт есть)

- Поля AG-UI читаются локальными схемами (`model/chat.ts`, `model/follow.ts`), а не `vQaRunResult` / `vRunCustomValue`.

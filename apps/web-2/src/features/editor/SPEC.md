# editor

Операции: publicProfileById, linkPreview, createBlock

Редактор блоков страниц-уроков и постов обсуждений: одно ядро Tiptap 3.31 с пресетами `authoring`, `view`,
`discussion`. Схема документа перенесена из `apps/web/src/components/Objects/Editor/Extensions` (имена узлов,
теги, выражения содержимого, атрибуты по умолчанию) и живёт в `model/schema` без DOM; виды узлов - в `ui/nodes`.
Публичный API (`index.ts`): ленивые `BlockEditor` (`activityId`, `content`, `onChange`), `BlockViewer`,
`DiscussionEditor` и чистые `normalizeDocument`, `extractPlainText`, `stripEmptyFileBlocks`, `EMPTY_DOCUMENT`.
Файлы загружаются общим `useUpload` (createUpload -> PUT -> finalizeUpload) и закрепляются createBlock.

## Поведение

- B-EDT-01 Каждый узел старой схемы (абзацы, заголовки, списки, цитата, линия, перенос, код, таблицы, отметки
  bold/italic/strike/underline/code/link; calloutInfo, calloutWarning, badge, button, embedBlock, flipcard,
  blockImage, blockPDF, blockVideo, blockMathEquation, scenarios, blockUser, blockWebPreview; в обсуждениях image)
  загружается и сохраняется без потери узлов и атрибутов. Неизвестный узел - ошибка, а не молчаливая потеря.
- B-EDT-02 Документы со старым узлом `blockEmbed` читаются как `embedBlock` (D-01, таблица ниже); нормализация
  идемпотентна, после неё в документе нет `blockEmbed`.
- B-EDT-03 YouTube встраивается одним способом: `embedBlock` типа `youtube`, iframe с youtube-nocookie.com.
  Старый узел `youtube` (@tiptap/extension-youtube) читается как такой `embedBlock`.
- B-EDT-04 Языки блоков кода: псевдонимы (kt, py, ts...) приводятся к одному имени, неизвестный - обычный текст;
  блоку без языка, похожему на Kotlin, ставится `kotlin`. Код подсвечивается shiki (грамматика грузится при
  первом использовании).
- B-EDT-05 Заголовки получают уникальные стабильные `id` (якоря): сохранённый id не меняется, пустой и
  повторный заполняются; кириллица и казахские буквы сохраняются.
- B-EDT-06 Блоки изображения, PDF и видео без загруженного файла (в том числе пока файл загружается) не
  сохраняются (UX-058); пустой документ сохраняется как один пустой абзац.
- B-EDT-07 Текст документа для сводок и поиска включает текст карточек и формул; у старого HTML снимаются теги.
- B-EDT-08 Встраивание грузится только по https; провайдеры получают адрес для iframe (Google Docs -> /preview,
  Excalidraw/tldraw -> embed=1, Figma, Vimeo, CodePen, Gist, Spotify...). Страница другого известного сервиса -
  тип `url`. iframe в sandbox, без доступа к нашему окну.
- B-EDT-09 Просмотр: все узлы показаны токенами кита, без поля ввода; карточка переворачивается и обратно,
  сценарий идёт по выбранному варианту и начинается заново; ширина и высота хранятся и применяются атрибутами.
- B-EDT-10 Авторинг: одно меню блоков. «/» в пустой строке открывает его у курсора (символ не печатается),
  кнопка «Вставить блок» на панели - под кнопкой; фокус в поиске, ввод фильтрует по названию, стрелки и Enter
  вставляют, Escape закрывает и возвращает фокус в текст. «/» внутри текста печатается как символ. Пустой
  атомарный блок сразу показывает свою форму.
- B-EDT-11 Панель форматирования: стиль текста (абзац, заголовок 1-3), жирный, курсив, подчёркнутый,
  зачёркнутый, код, списки, цитата, блок кода, ссылка (диалог), отмена/повтор; нажатая кнопка показывает
  форматирование под курсором; у каждой иконки подпись и подсказка.
- B-EDT-12 Встраивание в авторинге: поле адреса; не-https адрес - ошибка под полем; провайдер определяется сам.
- B-EDT-13 Формула: LaTeX в поле, KaTeX рисует сразу; ошибка в записи - текст ошибки, редактор не падает.
- B-EDT-14 Обсуждения: текст, код, ссылки, изображения; старый HTML пост (1 из 2 в проде) проходит sanitize() и
  редактируется; меню блоков нет. Пост и в просмотре читается схемой поста (пресет `discussion-view`): блоков урока
  нет, встраивание старого поста - ссылка на его адрес, не iframe.
- B-EDT-15 Блок пользователя показывает публичную карточку (publicProfileById); превью ссылки заполняется
  сервером (linkPreview) и открывает сайт в новой вкладке.
- B-EDT-16 onChange отдаёт канонический JSON: только `embedBlock`, без пустых файловых блоков.
- B-EDT-17 Изображение, PDF, видео: пустой блок показывает выбор файла (`FileInput`, назначение `block-image`,
  `block-pdf`, `block-video`: типы и размер под полем). Файл загружается сразу, прогресс и ошибка - внутри
  блока; загрузка закрепляется за активностью (createBlock), блок хранит `{block_uuid, content: {file_id,
file_key, file_format, file_name}}` и показывает файл по `/content/<file_key>`. Отказ закрепления - текст
  ошибки в блоке, документ не меняется.
- B-EDT-18 Изображение из буфера обмена (вставка) и изображение, PDF или видео, брошенные на страницу, становятся
  блоком своего типа в месте вставки/броска и сразу загружаются с прогрессом в блоке. Файл другого типа редактор
  не перехватывает; файл, брошенный на пустой файловый блок, загружается в этот блок.
- B-EDT-19 Видео из хранилища: нативный `<video>` с кнопками кита (воспроизведение/пауза, позиция ползунком,
  время, звук, полный экран); YouTube и другие сервисы - только `embedBlock`. PDF: iframe того же источника без
  sandbox (Chromium не показывает PDF в sandbox-фрейме; чужой адрес не показывается) и ссылка «Открыть PDF».
- B-EDT-20 В посте обсуждения изображение вставляется кнопкой «Добавить изображение» или вставкой из буфера:
  загрузка `discussion-image` (до 5 МБ), узел изображения с `/content/<key>`; пост забирает его через `upload_ids`.
- B-EDT-21 iframe встраивания - только https-адрес на хосте сервиса из каталога старого веба (и ppt-online.org из
  старых `embedCode`): никогда наш origin, относительный путь, `/content/`, `/ab-*`, адрес с логином. Голый текст -
  id YouTube, только если это ровно 11 символов `[A-Za-z0-9_-]`. `allow-same-origin` в sandbox - только у плееров,
  которым нужно своё хранилище (youtube-nocookie, Vimeo, Google, Spotify, Excalidraw, tldraw, Figma, CodePen);
  остальные сервисы - в непрозрачном origin.
- B-EDT-22 Файл блока - всегда `/content/<key>` с кодированием каждого сегмента; ключ с `..`, ведущим или двойным
  `/`, `\`, `?`, `#`, `%` (и значит закодированными их формами) или управляющим символом - не файл. PDF-фрейм
  показывает только путь нашего origin под `/content/`, `/ab-private/`, `/ab-public/`, `/api/v2/` без `..` и `\`
  (в том числе закодированных); иначе фрейма нет.

## D-01 (серверная миграция `activities.content`)

`blockEmbed {embedUrl, embedCode, embedType, embedHeight, embedWidth, alignment}` ->
`embedBlock {type, url, width, height}`: `url` = `embedUrl` (trim) или `src` первого iframe из `embedCode`;
`type` = youtube (youtube.com, youtu.be), google-docs/-slides/-sheets (docs.google.com/document|presentation|
spreadsheets), google-forms (docs.google.com/forms, forms.gle), иначе `url`; `width` = `embedWidth` или '100%';
`height` = `embedHeight` (число) или 300. Отбрасываются `embedType`, пустой `embedCode`, `alignment`.

## Изменено

- Цвет значка, кнопки и карточки (`color`) хранится, но не рисуется палитрой: только токены (DESIGN 1.3).
- Выравнивание `blockEmbed` не переносится: встраивание уже колонки всегда по центру (1 узел в проде, 91%).
- «/»-меню старого веба (подсказка по набранному тексту) стало якорным списком с собственным полем поиска;
  кнопка «Вставить блок» открывает тот же список, отдельного меню панели нет.
- Видео без artplayer и HLS (HLS в данных нет): кнопки кита, без скорости воспроизведения и картинки в картинке.
- Callout рисуется общим стилем `ab-prose` (`data-callout`); своих стилей типографики у фичи нет.
- Копирование кода в просмотре без тоста (тост только после мутации): кнопка меняет подпись.

## Не переносится

- Не переносится после D-01 (фаза 9): ветки `blockEmbed` и `youtube` в `normalizeDocument()` удаляются вместе
  со строками этой спецификации о них.
- Встраивание по коду (`embedCode` с HTML): исполнение чужого HTML небезопасно; в проде 0 таких узлов.
- Редактор сценариев (модальное окно) и правка эмодзи/цвета значка: 0 и 2 узла в проде; узлы читаются и
  показываются, сценарии проходятся.
- Пресет `interactive` старого веба = `view`; `viewing` = `view`.
- Счётчик символов, AI-вставка markdown в авторинг, подсветка блока под курсором (Focus): нет потребителя.
- `listBlocks`, `getBlock`, `deleteBlock` (удалить с сервера): блок хранит `file_key` в документе, а сохранение
  содержимого само освобождает загрузку блока, которого в нём нет (сервер, BUG-263); списка вложений нет в спецификации.
- Изменение размера и выравнивания изображения и PDF мышью: сохранённые `size`/`alignment` применяются, правки нет.
